# 角色注意力巡检

由当前主代理亲自观察和判断，减少用户逐张截图、逐项指出问题的负担。本 skill
组织主动问题发现与漏检学习；技术实现继续使用既有制作 skill。它不新增感知能力，
也不保证穷尽所有问题。检查表完成不代表审美合格。

## 开始时

读取实际交付版本、用户已认可的性质、任务范围和本集上轮记录。找到现有原片、
参考与采样工具，主动取材；不要因为动态难评就先找外部评分模型或要求用户截图。
先看画面写可见事实，再查实现原因，避免只发现自己熟悉的参数能修的问题。

**首次巡检须覆盖任务范围，不能只查用户点名的部位。** 修订轮复看改动区域、
相邻结构、完整角色和受影响的动作；已有有效且未受影响的证据可以引用。
整体角色任务包含两侧/后侧、手足和道具；单张头像不能声称完成全身检查。
只请求分析时交付诊断；已授权修片时继续制作、复验，不以列出问题代替修改。

**新集先做基线对照。** 新角色的代表性试片同时对照最近已接受的成片和外部参考，
不能只与自己刚做坏的第一版相比。首轮至少看完整人物、近景和主动作；完整衣甲、
人物身份或行动可读性退步时，先解决该退步再扩做。已经扩做才发现退步，保留这个
执行失误，不把多轮补救写成成功升级。迭代轮数、修复数量和功能数量不是质量证据。

## 怎样遍历注意力

读取 [注意力维度](references/attention-dimensions.json)。每轮聚焦一组关系，
完成观察后再切换，不把所有问题塞进一次“整体看起来怎么样”的判断：

1. **整体与身份**：先写正常观看尺寸下的直观表现和最突出的不协调，暂不看旧诊断。
2. **结构与连接**：脸、头颈、头发、躯干、四肢、衣甲、手足。从起点沿结构走到
   末端及相邻连接；问“应该出现却没出现的结构是什么”，不只找异常像素。
3. **时间与意图**：视线、微表情、重心、步态、发力、受击、跟随和收势。
   同一动作按预备→执行→接触/转折→恢复追踪；也检查倾听者与动作发起者的关系。
4. **镜头中的整体效果**：回到完整人物和实际画幅，查遮挡、大小、剪影、效果与
   声画配合。漂亮局部、光效或正确脚点不能抵消人物僵硬。
5. **开放复查**：暂时放下清单，再看完整片段。记录清单外的不协调、相邻部位
   之间的矛盾，以及“所有局部都正常但组合不好看”的情况，不为凑数量强找缺陷。

维度是注意方向，不是统一审美公式。按角色、画风、动作意图解释差异；静止可以是
表演，简化可以是设计。先问画面有没有表达所需关系，再决定是否增加动作或细节。

## 取证和比较

- 记录文件版本/摘要、时间段、角色、机位和实际查看方式。静帧用于结构，带时间的
  连续帧用于动作衔接；需要更细判断时加密接触、换脚、转面交界。正常速度观看、
  慢放和抽帧分别记录，不能互相冒充。
- 剧情 cue 只用于定位候选窗口，先解码确认要评的部位和行为确实可见。例如发现
  线索的 cue 可能对应地面插入镜头，不能直接拿它验证眼神；主动寻找相邻反应镜头。
- 比较参考与当前片时，先核对动作意图、角度、坡度、速度和遮挡是否可比。
  风格参考不能当作精确步长或身体比例标定。修改前后使用相同条件。
- 视野太小、脚被挡住、缺少动作前后过程时，主动补材料，标 `needs_evidence`；
  不能把没看清写成没有问题。诊断机位用于查因，最终机位用于确认观众能否读到。
- 对每项判断分开写**可见事实、原因假设、修复验证**。先确认问题在实际像素里，
  再查几何、绑定、时序或镜头。不从变量名和新增功能推断观感改善。

## 留下可检查的巡检记录

在 episode 的 `storyboard/character_attention/` 保存记录，避免只在对话里记住。
以下工具只初始化与校验覆盖记录，**不分析画面，不判定美丑，也不调用外部模型**：

```powershell
python ../dula-skills/character-attention-review/scripts/review_record.py init `
  --source ./episodes/example/output/final.mp4 `
  --output ./episodes/example/storyboard/character_attention/r1.json `
  --subjects hero enemy --window entry:20:27 --window strike:56:59
python ../dula-skills/character-attention-review/scripts/review_record.py check `
  ./episodes/example/storyboard/character_attention/r1.json
```

初始化每个角色×维度为 `unreviewed`。实际观察后逐项填写：

| 状态 | 含义与所需记录 |
|---|---|
| `finding` | 有具体问题；写观察、证据，并关联问题条目 |
| `no_issue_observed` | 仅在已看范围暂未见明显问题；写观察依据，非永久合格 |
| `needs_evidence` | 被挡、尺度不足或时间覆盖不足；写缺口和下一步补证 |
| `not_applicable` | 本范围没有该行为或结构；写原因，不能用来跳过难查的项目 |
| `unreviewed` | 尚未执行；不得报告巡检完成 |

证据路径相对记录文件，至少有时间位置与查看方式。可引用以前实际看过的材料，
但应核对版本与适用范围。覆盖工具返回“记录完整”也允许存在待修问题；
未检查/待补证返回退出码 2，失效来源/记录错误返回 1。脚本无法证明主代理真的看过，
需由实际视觉调用与具体观察共同支撑。
`coverage_complete` 只描述所声明角色与时窗的记录覆盖，不能推广为全角色、全片
或所有角度均已验收。局部试跑可保留缺口，实际修片任务仍须主动补足相关证据。

每个 `evidence` 元素使用 `path`、实际文件的 `sha256`、`window`（所声明时窗的 ID）、
`at`（原片秒数列表）、`method`。`method` 取 `still`、`ordered_frames`、`realtime`、
`slow_motion`、`audio_listening` 或 `audiovisual`，按实际输入填写。
例如解码帧列写 `{"path":"frames.jpg","sha256":"实际摘要","window":"entry",
"at":[20,20.1,20.2],"method":"ordered_frames"}`，不得将示例文字作为实际摘要。

问题记录包含角色、维度、来源、可见事实、证据、影响、优先级、原因假设和下一步。
来源区分 `user_reported`、`self_found`、`retrospective`，重复用户反馈不算自主发现。
修复状态与覆盖状态分开：确认缺陷可以完成该项观察，但不意味着缺陷已修好。
`issues` 字段为 `id/subject/dimension/origin/status/fact/impact/priority/hypothesis/
next_action/evidence`。状态为 `open/in_progress/fixed/deferred/disproven`；关闭时补
`result/verification`，修好还需 `change`。`iterations` 保存前后证据与收益/退步，
`misses` 按漏检学习参考留原判断和后来发现。

## 从问题推进到修改

优先处理最破坏身份、身体可信感或行动可读性的项目，每轮集中于一两项可见改善。
经用户授权的普通局部修订直接继续，不把每轮制作选择交还用户。

| 问题所在 | 修复入口 |
|---|---|
| 造型、比例、脸发、身体结构 | [character-modeler](../character-modeler/SKILL.md)，具体关系见其人物审美参考 |
| 变形、全身受力、动作与镜头修型 | [direct-animation-craft](../direct-animation-craft/SKILL.md) |
| 起步、换脚、停步、转身 | [walk-director](../walk-director/SKILL.md) |
| 注意对象、台词意图与表情时点 | [performance-director](../performance-director/SKILL.md)，先确认实际执行层 |
| 明暗、轮廓与二维画面组织 | [cel-look](../cel-look/SKILL.md) |
| 发力人声、Foley与声画配合 | [direct-episode-audio](../direct-episode-audio/SKILL.md)，保留已认可对白和音乐 |

复看目标缺陷是否减轻、是否过修、是否伤及相邻部位和已认可性质；最后返回完整
镜头。只有实际修改并看到收益，才能标 `fixed`。每次修复保留前后证据和具体结果。
连续无收益时检查原因假设与实现生效范围，换可验证的修法；不要无限增加参数，
也不要通过藏掉动作、改变比较条件来制造改善。输出未解决项和当前阻碍。

追查动作造成的状态变化：桥板断裂后人站在哪里、救回后谁继续承重、道具卸载后
怎样进入下一动作。把动作结束后的一段也纳入复看，避免局部接触正确而因果不成立。
若局部修好了但整体仍弱，应明确写“局部缺陷修复／整片未达目标”，并重新选择
制作路线或角色样板；不能把审查完成当成自动制作能力已经达标。

## 从漏检继续学习

后来发现的问题，无论来自用户、自己的后续复看或另一镜头，按
[漏检学习与回测](references/miss-learning.md) 处理。保留最初判断，不把后来
知道的答案补写成“当时已发现”。新增有效的注意提示，同时记录反例以防过修。

评价这套 skill 的效果，观察严重漏项、同类复发、修复退步和用户纠正负担的变化。
未发现的问题没有可靠分母，不编造“发现率 100%”。旧片带答案回测和新片探索分列；
直到有跨片段证据，才扩大独立处理范围。日常查错和迭代由主代理承担，用户无需
每轮参与；最终风格偏好仍以用户为准。

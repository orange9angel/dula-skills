# 漏检学习与回测

本 skill 的改进单位是“能把注意力引向有效证据的观察方法”，不是越来越长的
禁令或某个角色的专用比例。用户后续反馈是重要来源，但不是唯一来源：
自主复看、镜头转换、修订回归和同类新片段都可揭露漏检。

## 每个漏检保留什么

在 episode 的巡检记录旁保存案例。写清：

- **原始判断**：哪个版本、哪次记录、哪些角色/时间/视图；当时结论是什么。
- **后来发现**：谁发现、何时发现、具体可见事实与证据。原片当时已有的问题与
  新修订引入的退步分开；后者不能伪装成旧版漏检。
- **漏检环节**：没取到有效画面；取到了但没看该区域；看了但判断错误；
  被改动参数或已有结论引导；发现了却错误降级；或修复后没查相邻副作用。
- **注意提示**：下次在什么情形下，沿哪条结构/动作关系看，什么证据能支持判断。
  示例：“沿耳顶到耳垂，再到颌后缘和颈根”，比“耳朵检查更仔细”可执行。
- **反例和边界**：什么合理设计不应被误报；修复不足和修复过量分别是什么。
- **回测**：旧片能否复现问题；另一段是否适用；修复是否有效、有无新退步。
  标明 `未测试 / 带提示复现 / 拓展片段试用 / 跨片段有支持 / 不适用或误报`。

先修正文档中已有提示的表达和触发位置，合并同类提示；确有新关系才增加维度。
若问题来自执行漏项，优先修覆盖与证据要求，不继续复制同一句提醒。
无收益的提示要缩小范围或删除，避免清单噪声让主问题再次被淹没。

## 怎样试用而不自我暗示

1. 对新片段先保存未标注原图/连续画面，使用通用维度独立写观察，再读该片段的
   历史问题单或实现说明。已在上下文里见过答案时，如实标为带提示复查。
2. 用旧失败片证明提示能指向正确的关系；用邻近正常片或已认可性质检查误报。
   参考不足或风格不同就记录不确定，不能硬造一个“正常标准”。
3. 下一处不同时间/动作/角色继续试用，检查是否能迁移。新时间点不自动等于盲测，
   也不自动证明已经提高了发现率。
4. 跟踪实际修复：找对问题但修法失败，分别更新判断与实现记录，不能一起报成功。

## 怎样看是否减少人工迭代

按可比的片段或版本记录：

| 观察量 | 含义 |
|---|---|
| 交付前自主发现并修复的严重问题 | 必须有用户提示前的观察记录及修复证据 |
| 后来补充的严重漏项 | 按问题合并计数，避免拆成许多小项抬高成绩 |
| 同类复发 | 已有可执行提示、适用情形仍漏掉，查执行或提示设计 |
| 修复引入的新问题与误报 | 不能为“发现更多”而乱改已认可的性质 |
| 用户纠正负担 | 用户是否仍需逐帧截图、重复指出同一关系 |

没有完整真值就不计算总体召回率。用户没有反馈不代表无漏项；少查镜头、换更容易
的样本、把严重问题降级也不能算进步。短期先看个案，证据累积后再谈趋势。

## 启动案例：当前已有的漏检类型

以下来自既有记录，属于**带提示整理**，不计为新 skill 自主发现或修复成功。
详细画面与时间留在原 episode，skill 只保留可迁移的注意提示。

| 触发情形与旧盲点 | 下次注意提示 | 反例/过修风险 | 当前证据状态 |
|---|---|---|---|
| 发丝变细、接缝减少后，仍漏掉头套感 | 正常尺寸看颅顶与后脑大形，再沿发根—主束—发梢检查宽窄、负空间、耳后/后颈收束；把细线暂从注意中移开 | 光滑短发可以是设计；不能把所有发型拆成乱翘细束 | 已有用户反馈与当前画面复查，未有新修复验证 |
| 脚点稳定后，误把走路当作自然 | 连看提步前、换脚与收步，追踪髋—胸—头以及持械手的相对变化；看最后一步如何传递制动力 | 持重物、受伤、警戒可限制摆臂；不能一律加大摆动 | 既有步态帧列支持诊断，正常速度整体观感和新修法待验 |
| 局部眼睛/下颌改过，整脸仍不协调 | 回完整头颈，沿眼线—面颊—下颌—耳根—颈根检查比例与连接；区分连续无缝和关系正确 | 直下颌、尖下巴本身不是缺陷，不能普遍磨圆 | 既有角色审美复盘明确记录多次用户补漏 |
| 手臂与光效在动，身体发力仍空 | 连看支撑、髋胸肩传递、末端路径、防守者脸和身体响应，再看余力 | 魔法/刻意克制也要有意图依据，不能给每个动作套同一大幅预备 | 当前战斗研究支持诊断，未有新动作修复验证 |

原案例方法详见
[人物审美判断](../../character-modeler/references/character-aesthetics.md)、
[人物骨肉与受力表演](../../direct-animation-craft/references/embodied-character-performance.md)。

## 首次试跑暴露的取证错误

2026-10-20，在 `stardust_clad_s1e2` 的局部试跑中，主代理发现旧研究把
128–132秒计划为眼神样片，而最终 MP4 在128–131.8秒主要展示地面导火槽和腿。
这属于**审查计划错误**，不能因此断言插入镜头本身拍错。实际脸部近景在132秒后。
旧计划保留并追加纠正，记录见该集 `storyboard/character_attention/r27_trial.json`
的 M01；没有将这次发现改写为以前已知道。

新增提示：从剧情 cue 选窗后，先确认观察对象在画幅中、时间覆盖足够，再开始
维度判断；不适用时主动移到邻近实际镜头。本例已补看132–137秒，证明选窗错误
得到纠正，**不证明表情已经改善或整套 skill 已能独立发现所有问题**。

## 新集实验：查出问题不等于做出更好的角色

2026-10-20，`stardust_clad_s1e3` 自主制作实验出现两类执行漏项：

- 重搭身体后，近景面部有更多明暗，但全身的战壳、腰部和肩臂关系退步。主代理
  经多轮画像修订才充分回到完整人物与上一集对照。这里原来就有“肉体感不等于
  露肤”“保留已认可性质”的提示，问题在执行顺序，不能假装是新增概念解决了它。
  新提示：代表性试片必须同时对照已接受基线，不只对照本次更差的原型。
- 救援接触点靠近后，仍漏掉获救者落回已损坏桥板的后果。后续开放复查看出，
  将破坏限定为前半桥面、落点改到完好的后半桥面，重新检查完整救援过程。
  新提示：沿动作追到状态变化之后，再看下一动作的支撑与道具关系。

反例：故意坠落、受控悬空和失衡可以成立，不能强行把所有脚放回地面；衣甲简化
可以是设计，但不能自行把用户认可的系列造型改成简陋替身。

该集保留了原型、修订与失败记录；主代理在查看过的画面中仍判断新片整体未超过
接受基线，距参考的形体、发型和表演明显有差距。局部修复不构成整套工艺成功。
具体证据、未解决项与查看方式放在该集 `storyboard/character_attention/`，
不可把本案例描述为无人介入即可稳定达到商业动画质量的证明。

## 恢复试片中的错误继承

同日S1E3恢复试片R3恢复了较完整的衣甲、环境材质和光影，却直接沿用了前集宫殿
空间与音乐。用户明确指出新集的剧情、背景和音乐应当改变，只有剧情仍在原处才
沿用。这里是**创作范围判断错误**，不能因渲染细节恢复而宣称新集整体进步。
后续转向本集云峡送药目标、独立转运台和新配乐；具体成片判断继续留在episode。

可迁移提示：对照基线时分别问“哪些制作能力值得继承”“哪些内容属于上一集”。
检查新场景的轮廓、空间关系与剧情用途，以及音乐实际来源摘要，不能只看文件名
或色调。此提示来自用户纠正，不算自主发现；新内容生成也不证明肉体感和表演达标。

### 内容独立后的再反馈

用户随后再次指出肉体、脸、发型和打斗仍无提升。独立背景、剧情目标和音乐只满足
内容要求，不是角色质量的替代证据。头发学习试样中，去掉圆管明暗后仍有帽壳感；
变薄后还可能失去蓬松量。审查需并列“旧缺陷减轻”和“新缺陷/身份退步”，
不能因为实现方法符合教程术语就判合格。具体材料与失败试样见
[发型学习记录](../../character-modeler/references/layered-hair-study.md)。

记录有效性也需抽查文字本身：Windows经shell管道把中文送入脚本时，本轮发现
历史JSON的观察文字变成问号，结构校验仍返回有效。已依据原有审片正文恢复英文
观察，保持原状态和证据。以后用明确UTF-8文件或直接文件补丁写记录，并抽查实际
文字；非空字符串和JSON语法正确不能证明审查内容有效。

### 发型明暗的具体漏检

同轮 R6 已被判为贴头圆壳，但原审查仅记“去掉圆管亮纹”，漏掉了侧后面跨束的
等高亮带及统一椭球受光。用户再次指出光线与发束控制后，多角度对照才把两项
具体化。这是用户触发的补漏，不能回写为上轮已自主发现。

新增发型注意提示：分别沿外轮廓、主束中段与亮面走一遍，确认三者描述同一种
弯曲和遮挡关系；比较去掉旧问题后是否损失体积。`cel-look` 已有横亮带提示，
所以此例也说明已有规则未执行，需要实际对照图和像素观察，而非再加技能名称。
反例：有设计依据的带状高光、光滑短发可以成立；不能一律取消亮带或添加碎发。
当前仅完成参考诊断，尚无新修法收益证据。详细资料见
[发型学习记录](../../character-modeler/references/layered-hair-study.md)。

### 连贯覆盖之后仍漏掉长度与耳部造型

2026-10-21 用户认可暗色连贯方向后，仍指出鬓角和后脑没有达到所需长度、
耳朵怪异，随后补充发际线不能后移。上轮已有侧后图，问题是过度关注是否漏肤，
没有充分判断末端位置和相邻耳部造型；原“色块连贯”的局部结论保留。

下一次分别检查：发尾相对耳垂/颌后缘/颈根的落点；耳轮与耳垂的连接、
耳面朝向及与脸的色差；额前生长位置和刘海覆盖边缘。加长后查下段是否成为
直筒或布片，改前缘后查额头是否被抬高。短发、正常遮耳和简化耳线都是反例，
不把当前用户的及颈长度推广成所有角色的规定。
本例为用户触发、带提示复查；当前试样改善长度与白色饰件耳，前缘自然度
仍不足。没有跨角色盲测或“自动发现所有问题”的证据。

### 检查了端点，仍漏掉相邻区域

同轮用户再指出耳上、耳后到颈部的覆盖不足，说明“鬓角够长、后发及颈”没有覆盖
两者之间的发区。原长度改进保留；这个新问题来源为 `user_reported`。新增注意提示：
沿相邻区域连续走完边界，标出哪些皮肤露出属于设计，哪些是未接上的发区。
适用于当前要求的发型；剃短、露耳或短后发可以是有效设计。

R4 局部连接改善后，用户仍指出耳后不足、额中偏秃和假发感。不要将“闭合缺口”
升级成“发型自然”。后续额中补发的低头帧暴露了新增细缝，复看才修掉；这属于
自查发现的修复副作用，不应改写成原问题已经自主发现。细节增加后重看相邻面和
完整头像，尤其区分“已有该功能”和“正常画幅读得出来”：本轮旧眼睛已有小高光，
用户期望的是更明确的虹膜与反光关系，不能声称从零补上此前不存在的高光。

## 长剧试制：数值通过后沿关系复看

2026-10-21，S1E3 `longform` 试制中的三例，均保留在本集审片记录：

- **脚点稳定，身体仍像蹲行。** R11解码帧暴露持续屈膝；R13减小普通行走下沉
  后改善。原脚点稳定结论没有被否定，但不能推广为自然度结论。下一次在支撑
  相追踪脚踝—膝—髋—胸，不以“零滑移”结束判断；救援低姿后退是合理反例。
- **头中心可见，半张脸仍被挡。** 先前只检查单一目标射线和较窄的人物代理，
  漏掉肩甲与横栏覆盖下脸。B03与B34分别补看真实近景，再扩大相关区域的
  遮挡检查；不要因为头顶或眼睛露出就认为对白表演可读。
- **动作连续性补了，摄影仍漏拍。** 独立剧本批评指出B42救索需要从前臂移到
  腰间承重点；动作补完后，R14实际镜头仍拍旁观者。R15给转扣留明确窗口，
  四张有序画面能看到绳端随手移向腰环。应沿“接触点—承重者—腾出的手—
  下一次抓握”检查，并确认这些变化在实际剪辑里出现。静止持绳不需重复特写。

以上包含带提示复查与自主发现的实施漏项，不是跨片盲测。它们支持局部修法和
注意方向，尚不支持“角色肉体感或45分钟动态表演已达商业标准”。具体实现分别
回到 `walk-director`、`scene-designer` 和 `cel-look`，不在本 skill 复制求解代码。

### 编码后逐段复查仍发现的漏项

同一长剧R1的实际编码段又暴露：入场裁头、托盆挡嘴且风灯抢占双手、救援居民
遮脸，以及避墙机位离主体过近。此前1184时刻抽样没有报这些问题，原检查范围
不能改写成“当时已覆盖全身与所有遮挡”。有效补查是沿“谁在说／谁在做—哪只手—
哪个道具—所有前景人物—最终取景”走完关系，不只扩大头中心射线数量。

另外，出拳侧的镜头试验发现原有拳风并非完全缺失，而是被身体挡住。应先判断
效果有没有进入实际画幅，再决定加粒子或重做动作。前景遮挡、侧面构图和共同
持物都可以有意成立；要求的是剧情主体能被读到，不是所有角色始终完整露出。
本例候选经局部实际图像复验，整片仍需要最终编码检查，不能据此宣称无漏项。

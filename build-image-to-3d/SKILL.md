# 图像到可制作的三维资产

技能负责组织生成、加工、接入与验收；几何重建由选定的模型或服务执行。
只有文件和说明时报告“流程已建立”，只有静态网格时报告“静态资产”，不要声称
已得到可表演的角色或复现某个生成平台的能力。

## 先决定重建什么

| 输入与使用方式 | 优先路线 | 必须保留的边界 |
|---|---|---|
| 天空、很远的城市 | 全景天穹或镜头投影，沿用 [混合场景](../hybrid-craft-scene/SKILL.md) | 单张宽幅图不是完整球面全景；天空通常不需要生成实体网格 |
| 建筑、地形，需要小幅移镜 | 分层图像 + 深度代理或相机投影 | 单视图深度不含背面；补显露区并标注可用机位范围 |
| 石块、拳甲、管件等独立物件，需要转面 | 图转网格，清理后导入 GLB | 轮廓、孔洞、尺度、底部接触比细小纹理优先 |
| 会讲话、抓握、跑打的主角 | 多视图造型 + 连续网格 + 身体绑定 + 独立面部系统 | 自动绑定不等于表情、手指或关节变形合格 |

已有精确交互结构可保留，用生成资产替换外观、附加部件或非交互道具。
“几何归程序化”是旧混合场景路线的选择，不是禁止导入模型的工作区规则。

## 准备有约束的输入

1. 阅读当前 episode 的角色、运行入口、最终视频与资产来源；确认目标是静态道具、
   局部装备还是全身角色。复用已有合格资产与连续网格，别仅因它们由代码创建就重做。
2. 单体参考尽量完整、少遮挡、弱透视，保持方向标注和背景分离。角色用中性表情和
   放松 A/T 姿态，手臂离躯干、双腿分开；手指、装备、衣摆不能融成一块。
3. 多视图必须是同一造型的正/侧/背约束；独立生成的相似人像不自动算一致的多视图。
   需要生成或编辑参考图时沿用 [连续图像技能](../build-continuous-story-images/SKILL.md)。
4. 对角色标清左/右、装甲附着点和裸露区域。身体、可变装甲、武器可分别建模与绑定，
   避免把三种装甲状态烤成一个无法变形的网格。单图看不见的背部是推断，单独验收。

## 执行生成

根据已有账号、本地硬件、风格与输出需求选一个后端，先跑一个代表物件。
调用前核对当时的官方接口/版本、输入类型、输出格式、绑定能力和适用许可；
本技能不硬编码可能过时的模型名、价格或显存估值。

已有授权覆盖的调用继续执行，不重复索要同一授权。仅在确实缺少凭据、费用范围
或必要输入时询问，并继续完成可离线处理的准备工作。

对异步服务保存输入文件哈希、生成配置和 task ID。提交超时先查任务状态，
不要盲目重复提交收费任务。下载输出到 episode 的候选资产目录，保留原始结果，
修型另存。密钥从环境读取，不能写入 source manifest 或输出日志。

来源记录至少包含：后端和版本、输入哈希、参数、任务 ID（如有）、输出哈希、
来源许可记录、生成时间。单位与正前向在清理阶段实测或显式标定，不能凭文件格式猜。

## 从“能看”到“能用”

先用 [scripts/inspect_glb.py](scripts/inspect_glb.py) 做离线清点：

```powershell
python dula-skills/build-image-to-3d/scripts/inspect_glb.py path/to/model.glb --out path/to/inventory.json
# 仅当选择了骨骼蒙皮路线时要求 skin；普通静态道具不需要。
python dula-skills/build-image-to-3d/scripts/inspect_glb.py path/to/actor.glb --require-skin
```

脚本检查 GLB 容器并列出静态三角面数、材质、蒙皮、变形目标和扩展。它不解码
几何缓冲、不验证权重数值、不测世界尺寸、不判断穿插或造型，也不替代正式 glTF 验证。
压缩扩展需要执行环境具备相应解码器；外部依赖必须随资产交付。

随后在实际导入环境完成：

- **形体**：看正、侧、背和剪影；修孔洞、悬浮碎片、粘连、重复面和错误法线。
  按最终投影尺寸减面，不能以固定面数替代形体验收。服装、头发、手和装备按动画需要分离。
- **变形**：角色重拓扑服务肩肘、髋膝、嘴眼的弯曲；测试蹲下、抬臂、握拳和转头。
  skin、joint 和 morph 的存在只证明有数据。自动骨架经修权重和修正形后才交付。
- **脸部**：眼神目标、眼睑、眉形/左右差异、嘴角情绪和说话视素分通道。
  可用 morph、局部网格或连续面部纹理，但不要让中性参考图中的眼嘴固定烤死。
- **材质**：去除与目标灯光矛盾的烘焙阴影；基础色使用 sRGB，法线/粗糙度/金属度
  作为线性数据。在目标灯光下比较角色与背景的明度、阴影软硬和细节尺度。
- **空间**：确定米制或 episode 的约定单位、脚底/物件底座锚点、正前向、缩放、
  装备挂点和碰撞代理。投影纹理沿用标定相机，不能把一张照片的透视当成 UV 材质。

接入 Dula 时先确认使用 `CharacterBase` 还是 episode 自包含 viewer。沿用其真实
姿态、口型与加载契约；异步资产加入 readyPromise 或现有等价等待机制。骨骼映射、
root motion、支撑脚与装备父级显式接入，不能凭“GLB 能打开”宣称动作可复用。
共享角色入 `dula-assets` 前先在当前 episode 的变体验证。

## 用短镜头判定是否值得推广

- 道具：转面、接地阴影、实际镜头里的遮挡和与角色的接触。
- 角色：一句对白带视线转移、一段抬手/握物、一段跨步发力。先完整表现意图、
  预备、接触和缓冲，再加次级运动。表演沿用 [动画作画监督](../direct-animation-craft/SKILL.md)。
- 小幅空间重建：真实相机路径的左右移动、仰俯、遮挡显露；不能拿静止正面图证明自由运镜。

保留同机位的原版、候选版、最终视频抽帧和连续片段，分别报告结构检查、动态检查、
审美限制。原片已认可的表演不能在换模型/换入口时丢失：核对运行模式与具体镜头。
诊断或创建技能的任务先交付试验和结论，不默认重制整集。

## 当前实现范围

已提供生产流程与离线 GLB 清点工具。没有附带模型权重，也没有内置或实测某家
收费生成 API 的端到端适配。实际生成时按当前可用后端补接，不能把检查工具当成生成器。

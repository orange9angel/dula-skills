# 生成原画与程序动作混合：有限二维角色

**适用边界更新：** 咖啡厅集用户随后明确要求 2D→3D 的真实三维跳舞，否决了
本路线用于该集。以下局部工艺仍可用于明确选择有限二维动画的任务，不能当作
用户已认可的三维替代方案。修订见 character-modeler 的三维舞蹈记录。

2026-10-17《半拍晴天》试验。原图角色与咖啡厅母版来自 imagegen，程序负责局部
脸部、前臂、腿部形变及蒸汽、镜头、字幕。适合正面聊天、轻微侧步与唱歌；不代表
任意转身、复杂跳舞或图生视频质量已经成立。原画的生成成本仍须计入。

## 已定位的问题与修法

- 把漂亮的生成头贴到简化程序身体上，静态也可能显得头身脱节。先用同机位短片
  验证完整角色；原画更协调时可以选择有限二维形变，但明确放弃的转面范围。
- 整张人物共用规则网格时，按屏幕行或宽范围决定肢体影响会把同一行的手、裙、
  长发拉在一起。补更多大矩形排除域曾造成破洞和残留手指。本轮实际采用源像素
  独立前臂层：语义区域内取肤色及手指像素、微扩展保住轮廓墨线，主体去掉该层，
  各层分别变形。袖口附近保留原位置，只做小幅肘弯，避免袖臂接缝撕裂。
- 遮挡区域原图没有画出来，移开手臂会暴露空缺。有限的隐藏发色补片可填本轮小幅
  动作，但不能拿一块色片推断大动作也成立；检查补片外轮廓和遮挡次序。
- 眼口清底若逐列从区域上下采色，可能采到刘海、眉毛或下颌墨线，闭眼时变成竖直
  黑条。`generated-portrait-paint.js` 新增可选 `samplePointTop/Bottom`，从确认
  干净的源肤色点采色，旧默认行为不变。不同角色独立标定，不复制眼位和清理域。
- 细节原画可随二维网格保留，嘴仍需真实绘制开口。原画笑线变宽不等于唱歌；
  最终角色人声总线门控、闭嘴段和实际脸部像素分别验收。

## 检查范围

1. 检查全身、半身与闭眼张口，重点看袖口、裙边、手指和脚底；别只看生成立绘。
2. 渲染顺序采样后按相反次序 seek，比较最终图像哈希，暴露历史状态依赖。
3. 支撑锚点轨迹可查明显滑步，不能冒充整张网格或全部接触已检测。
4. 已知歌词 DTW 和 ASR 不识别实际歌手分工。按提示词分配的男女/合唱段必须标记
   听审待定；静音门控通过也不能替代正常速度试听。
5. 自包含 viewer 的音频 `preload=auto` 曾阻塞 `networkidle`；截图用
   `domcontentloaded` 后等待显式图像/角色 ready，音频按需加载。文件存在不算 ready。

实际入口：`dula-assets/characters/sunprint/IllustratedCafeKid.js`，脸部共用
`dula-assets/lib/craft3d/generated-portrait-paint.js`；本集 `bootstrap.js` 使用
viewer 注册表，不伪装成 CharacterBase 或 `dula-render` 适配器。原画和影像证据
留在内容仓 `episodes/cat_leads_cafe_musical/`。这是一版有限动画试验，审美认可待用户。

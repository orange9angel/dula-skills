# Song Lip Sync（程序角色的歌唱口型）

适用：角色由程序绘制/Three.js 几何体构成（不走视频生成大模型），需要嘴型
跟随歌声或配音。参考实现：`dula-story/episodes/yuki_beat_ad`（V8→V14 五轮
迭代踩坑史），对齐侧深度教训见姊妹文档
`dula-skills/volc-song-gen/references/singing-performance.md`。

## 什么时候用 / 不用

- 用：程序角色唱跳 MV、配音对白、口播；有歌词/台词原文
- 不用：走视频生成模型（Seedance/OmniHuman 自带口型）；无台词的纯动作片

## 数据链路（顺序不可颠倒）

1. **人声分离**：Demucs 拆 vocals 轨。HPSS 的 harmonic 支**不是**纯人声
   （伴奏泄漏会让闭嘴段乱动嘴）。模型约 319MB，缓存复用。
2. **逐字对齐**：有原文就用 Whisper `find_alignment`（已知文本 DTW），
   不要用 `transcribe(initial_prompt=...)` 冒充对齐——后者是带提示的转写，
   字界不准。中文逐字编码，多字 token 不要机械均分时长。
3. **起音锚定**：DTW 字界有逐字抖动（实测 58/80 字偏差 >80ms）。用分离人声
   的 onset 包络把每个字起始吸附到 ±150ms 内的起音沿，预留 30ms 口型提前量
   （真人先摆嘴型后出声）。字窗必须不重叠（前字 end 要随之后移），
   重叠时旧字会遮住新字口型。
4. **拼音视素**：闭唇音（b/p/m）在声头前闭合、唇齿音（f）、A/E/I/O/U
   元音口型、长元音保持。**静音/休止强制闭嘴，且覆盖一切表情嘴型**
   （否则角色在间奏里保持张嘴笑，像假唱穿帮）。
5. **振幅包络要防颤音**：歌声强弱驱动开合度时，RMS 必须做非对称包络跟随
   （attack ≤20ms / release ≥250ms）+ ~100ms 低通。只做几 ms 平滑会让
   5-7Hz 颤音直接抽动下巴（V13 实测踩坑，V14 修复后调制深度降 61-97%）。

## 渲染侧

- 嘴型几何宁少勿滥：Q 版角色脸上，3-5 种可读的嘴形胜过 10 种读不出的。
  上下唇独立轮廓 + 开合度连续值是性价比最高的组合。
- 字幕逐字高亮（KTV 效果）与口型共用同一份对齐数据，零额外成本。

## 验收纪律

- 量化自查：逐字起音偏差分布（|误|>80ms 的字数）、休止帧闭嘴率、
  颤音带调制深度。
- 但最终"像不像在唱"只有**正常速度人眼试听**能判定。不得从"检查帧通过/
  0ms 吸拍"推导出口型已获审美认可——V8/V9 两次被监制否决都是这个错误。

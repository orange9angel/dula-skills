# 生成绘画直接用于可动画三维角色

目标是保留文生图的画工，同时用三维维持体积、遮挡、绑定和运动。与混合场景
一样，生成图应成为实际进入渲染的材质或图层；不能照图重新画成简化程序图形，
再把简化模型的截图当作参考，声称还原了原画。

配合 [曲面角色](craft3d-drawn-characters.md)、[人物造型精修](../../direct-animation-craft/references/character-look-development.md)
和 [二维画面整理](../../cel-look/SKILL.md)。生图使用会话可用的 imagegen 工作流；
仅当需要多镜头连续图时再联用 build-continuous-story-images。

## 锁定美术目标，不增加一次无效重画

1. 已确认文生图可直接作为唯一身份与画风基准。记录年龄感、脸型、眼型、发型
   和服装识别点；不要先转换成较容易编码的简化参考图。
2. 原图的角度或遮挡不适合贴图时，生成**生产资产**：正投影颜色纹理、干净的
   脸面、前后发层、眉眼口局部图层。它们应实际进入渲染，并保留原画精细程度。
   说明每张图用于哪一层，不把只展示、未接入的漂亮图片称为角色实现。
3. 九宫格是可选的结构补充。缺侧脸/后脑信息时生成正、左右三分之四、左右侧、
   后侧、背、俯、仰；已有角度够用则省略。锁定身体左右、配件和年龄；生成图
   不是精确正投影。若各格矛盾，以已确认母图及实际角色结构纠正，不盲目照抄。
4. 保存原图、提示词、生产 PNG、输入输出关系及哈希；新增图不覆盖已确认母图。

## 实现分工

| 内容 | 主要责任 | 不能偷换为 |
|---|---|---|
| 脸型、额头、鼻、下巴 | 可转面的实际几何，按原画轮廓拟合 | 球面加大眼贴图 |
| 眉眼线、虹膜、鼻口细节 | 生成绘画的纹理/局部图层及 UV 对齐 | 重新用几个椭圆和贝塞尔弧简化 |
| 发型轮廓、发束前后关系 | 发壳与有厚度的束面，先匹配剪影 | 一块朝相机的完整头像卡片 |
| 发束线稿、绘制亮暗 | 与几何流向一致的实际颜色纹理 | 随机细线或统一高光横带 |
| 视线、眨眼、表情、口型 | 独立图层或局部变形，接原表演时钟 | 每帧重新生图或一张固定表情 |
| 身体、衣物、接触 | 复用成熟网格/绑定，必要处局部修型 | 生图后宣称手脚扭曲已解决 |

每一步先复用现有 `lib/craft3d`，必要的可执行扩展仍归 dula-assets。试验以独立
可切换模式接入既有 viewer，保留已认可的场景、声音与表演。先做一个角色和一段
真实对白，验证相似度、动作兼容与复用成本后再推广。

## 映射与动画纪律

- 先量原图的眼中心、内外角、眉、鼻尖、嘴、下巴和发际线，再定投影/UV。检查
  实际画面比例；不强把漂亮画稿拉伸到不匹配的旧头型上。
- 正面纹理不能凭空提供侧后图案。采用明确的 UV 图表或受覆盖范围约束的多视图
  投影；转面接缝、重复五官、远侧眼穿透和烘焙刘海的重复遮挡都要检查。
- 基础颜色使用 sRGB，数值遮罩不使用颜色解码。绘画本身已有色块时控制二次灯光，
  不再叠出蜡质高光；必要阴影仍服务体积与遮挡，脸、耳、颈的材质要统一。
- 可用 CanvasTexture 在曲面 UV 上合成原画图层。默认中性帧尽量保留原始像素；
  眨眼遮盖固定虹膜，视线在眼白范围移动，眉与嘴独立，嘴形跟随最终对白。
- 转头用头骨及真实曲面，不把五官永远朝镜头。需要视角修型时显式记录适用角度，
  不把只在正面成立的投影宣称为任意角度一致。二维头卡、曲面映射与完整三维
  是不同路线，交付时如实区分。
- 相似度失败先定位：原图到生产资产是否漂移、资产到 UV 是否变形、模型轮廓是否
  不匹配、着色是否二次损坏。不要一概归咎于生成后端或贴图分辨率。

## 直接对原图验收

出现“正面很像、斜角断层”时，先读
[多视角拟合与失败复盘](multiview-character-fit.md)。侧图混合、alpha 体积、
独立耳 UV 都有各自边界；不要把机制可运行误写为造型已解决。

保留三列证据：**已确认原图 → 实际使用的生产图层 → 模型渲染**。另做同机位
旧模型/新模型对照。参考与模型角度不一致时明确说明，不称为严格同机位比较。

静态检查头部近景和实际成片尺寸，动态检查左右转、俯仰、偏视、半眨/全闭、闭嘴/
开口和一段原对白。记录哪些绘制细节被保留、哪些角度失效；逆序 seek、浏览器
错误和视频帧数只验证实现，不代替美术判断。

用户认可人设图不等于认可模型。制作成功的标准是最终人物接近已确认原画，且
能完成需要的表演；不能用模型自己生成的九视图作为“独立还原能力”的证据。

## S1E4 直接绘画试验：已验证的机制与边界

共享实现是 `lib/craft3d/generated-face-paint.js`、`painted-hair-shell.js` 与
`characters/bioarmor/aoi-generated-paint.js`。生成脸面进入曲面 UV，生成前发进入
有厚度的曲面网格，后脑使用后视生产图；`cel=direct` 只对葵启用。原始母图及
派生生产图不是像素锁定的同一张画，须检查身份漂移。

- 正面保留精细睫线、虹膜与发丝，转头时由头骨带动实际曲面；它不是整头朝镜头
  的卡片。但单张前发投影即使加厚也不能恢复发束的三维走向，正侧面仍有薄壳
  和顶部接缝。此实现是可运行试验，不是任意视角已验收的角色方案。
- 只保留 alpha 网格中点在发区的方格会丢掉细发梢。完整网格配 alphaTest 能保留
  细节，边墙沿真实 alpha 轮廓插值，细丝厚度减小；仍须检查侧面小锯齿。
- 用前向 x 坐标投影整圈头发，侧面 UV 变化率趋近零，会拉成横条。后脑改用角度
  展开可缓解；后视图里的耳朵、脖子不得顺带烘进发帽。后发轮廓与独立束面仍需建模。
- 耳朵不能共用整张脸的正向投影：窄耳图会拉到太阳穴。没有独立耳 UV 时，先用
  简洁耳形保持结构，不能将变形纹理当细节。开放发帽的反面描边也会变成黑色大板。
- 眨眼局部底图保留上下肤色过渡，比纯肤色矩形遮盖更连贯；该局部修补仍不等于
  完整表情图集，较大表情和侧脸口型需要独立生产资产。
- 本地浏览器中 alphaToCoverage 使场景重复导出字节不同；本试验改回 alphaTest
  后逆序结果一致。这是本运行环境的发现，不推广为所有 GPU 的结论。

15 个脸部状态和 5 个场景时刻的回归检查只验证确定性、接入及浏览器错误。
颈领边界、头发次级摆动、腕部扭曲/握物接触不由这次贴图试验解决。先修图层与
束面的对应关系，再考虑补侧视投影；不要为凑齐九张图连续生成却不检查已接入结果。

技术依据：Three.js 的 [BufferGeometry](https://threejs.org/docs/pages/BufferGeometry.html)
支持顶点与 UV；[CanvasTexture](https://threejs.org/docs/pages/CanvasTexture.html) 支持画布纹理；
[MeshBasicMaterial](https://threejs.org/docs/pages/MeshBasicMaterial.html) 不受灯光影响并支持颜色贴图。
这些是可用机制，不是已解决角色多角度相似度的保证。以本地锁定版本和实际试片为准。

### V2：不要把绘制细节当作体积依据

- 用局部 alpha 密度决定发丝厚度，会把细线、透明小孔放大成起伏；即使换距离场，
  整张发图的侧壁仍可能读成厚纸。此次改为薄的曲面绘画层加连续闭合的大束体积，
  大束另用顺着曲线的 UV。检查体积不能伸出原画剪影，内部取样不得带透明黑底。
- 后脑 UV 在顶部应收敛到同一位置；一圈不同横坐标汇聚到同一个顶点，会产生
  扇形拉花。前发、后脑和马尾三者的纹理与体积分别检查，不只看正面。
  纵向 UV 硬截断也会把纹理边缘延伸成竖条；使用连续映射并检查取样是否带入耳颈。
- 改宽脸颊时同步调整局部 UV；模型负责新轮廓，原画旧下颌描线必须退出边界，
  否则生成一粗一细两条下巴。眉眼区域保持独立，不能把整张脸横向拉胖。
- 奶白衣物暗部与肤色会重叠，单个 RGB 比值不能作可靠语义。结合骨骼影响、
  静止姿态的袖长与领口区域；限制在真实肢体附近，不能用“身体两侧且低于袖口”
  这类宽泛范围，否则裙摆也被染成肤色。去原头部时另保护白领片。
  反向收紧为不连续的 x/y 范围，又会漏掉前臂，出现整块绿色“袖套”；应结合连续
  骨轴距离和蒙皮语义权重，复查真实袖口以及手臂、裙侧两边的误判。
- 调整中先复查新增错误，再产出交付证据。本次曾出现下睑切平虹膜、发束体积
  超出剪影、取样透明区变黑、裙侧误判为手臂；这些失败不能随候选新版覆盖掉。

用户已认可 `direct_paint_v1/render_r2` 的正面 neutral/talk/firm。后续实施应对照
该版本限制正面漂移，不为补全侧后方而牺牲认可的剪影。技术回归通过与用户认可
范围分别登记，后续 V2 候选不继承 R2 的审美通过状态。

### 侧面修订：投影保真与几何轮廓分开控制

- 保留正面 x/y 与绘制 UV，调整 z 方向的额鼻唇颌轮廓，可以减少正面漂移。
  轮廓按真实高度插值，限制过冲；鼻唇起伏仅影响面中部，不能把鼻尖高度扩展
  到整圈脸颊，否则三分之四出现宽凸嘴部。跨前后 UV 分区的接缝处，局部位移
  必须连续归零；新增轮廓后检查两侧接缝顶点，而非只查有限数值。
  在下巴等极窄截面，中央轮廓与整圈截面同时协调，避免侧缘反而比新的中央
  轮廓更靠前，造成交叉描线。虹膜附近可用局部较平的曲面承载绘画，眼睑外侧
  仍接回脸颊；检查斜角、侧面偏视和半眨，不能只针对一个静帧压缩虹膜贴图。
- 侧眼不可见时先排查遮挡。前发可保留原来的正面投影，同时让鬓发曲面绕到
  太阳穴，避免整片发图竖在眼前。马尾另设范围，防止鬓发后移把绘画层推到
  闭合发束内部，令正面漏出不匹配的高光。
- 脸面基础图剪掉耳区还不够：后续眼睛清底和睫线恢复也必须受同一脸区裁切。
  本轮发现局部矩形清底重新带入源图耳朵，转侧后出现第二组耳纹在太阳穴。
- 耳朵使用独立曲面 UV，取样已有生成脸图的耳区；贴图材质本色应为白色，
  再乘肤色会变橙。取样边缘留肤色余量，避免正面耳缘出现直线裁切痕。
- 侧面诊断可暂时隐藏头发看底层结构，但不能用裸头诊断图代替最终外观验收。
  同时检查头骨转动和相机绕行：大角度头颈变形与静止侧面造型是不同问题。

本轮沿用已有 `face_design_turnaround_v1/aoi_nine_views.png`，没有重新生成参考
或把生成侧脸当成模型截图。证据与实际代码分别归内容仓和资产仓；六秒无声
转头片仅用于连续造型检查，不能替代对白、腕部或接触表演验收。

### 同工艺接入第二角色：坐标与语义必须重新标定

- 共用的是头面、绘画、发壳和验证能力，不是前一角色的绝对高度与局部轮廓。
  雷晓试验独立标定眼高、原图原点、像素比例、鼻唇下颌、耳位和颈环；不能把葵的
  眼颊修型参数整体平移后当作新角色。共享 shader 的颈部阴影高度也须可选配置。
- 图层编辑即使明确要求保持坐标，生成结果仍可能自动缩放。先比较发旋、中央发尖、
  耳侧分束等多个锚点，再注册前发与脸层；不要从“画幅尺寸相同”推断已经对齐。
  原画保持不变，运行时投影注册参数和实际采用的 PNG 哈希同时记录。
- 单张发图的额前、耳外与后颈是不同空间区域。统一的 `headClearance` 最大值会
  把后颈发丝推到脸前，直接改 z 又可能拉出长纸片。必须按区域检查前发层、后帽、
  正反面 alpha 与边壁；静态语义裁切也要检查真实透明凹口，防止横切完整发束。
- 新绘画不一定适配旧角色硬编码的眼睑路径。使用独立源像素曲线、闭眼弧、清理域
  和有限偏视幅度；上下肤色采样若碰到眉间阴影，会在闭眼时留下竖条。中性、半闭、
  全闭、偏视和张口均实渲染，不能把状态数值在变等同于眉眼表演完整。
- 脸域裁切应覆盖所有动画绘制；域边缘的源肤色和基础肤色不同会形成太阳穴纵带。
  可在脸域内侧局部羽化，保留眼鼻口核心像素，并缓存遮罩与清理底片。无发图用于
  找接缝，最终仍须带发回查两侧转面。
- 参数进 GLSL 时要为带符号常量加括号。第二角色 `centerX` 和 `jaw.rootZ` 为负，
  原字符串 `x-${value}` 会生成 `x--0.012` 并编译失败。局部形变使用相对角色中心，
  不以世界 x=0 暗中假定对称；旧角色默认参数保持原样并做像素回归。
- 球形耳的下极横向半径趋零，单纯增加耳厚无法填补耳垂与脸之间的洞。按耳的局部
  下缘权重向脸内收，保留原 UV 图表，检查耳根连接及另一侧，不把耳垂拉成长条。

本次代码入口是 `lib/craft3d/generated-portrait-paint.js` 与
`characters/bioarmor/lei-generated-paint.js`；这是有限绘画表情和转面候选，
不是完整视素或任意大表情系统。不同角色各自一个 `current/`，不要覆盖前一角色
已选版本；原画、少量必要对照与失败文字记录留下，完成的试验媒体按授权实际清理。

### 分渲染域不等于恢复独立发束：雷晓分层小试未采用

用户认可男主当前外观后，明确要求无损试验、只有更好才替换。先保存源码、贴图、
视频和验证记录的完整基准，核对恢复清单，再以浏览器请求覆盖运行候选；正式
`current`不动。源码进Git仍要防换行转换破坏快照SHA；LFS文件核对OID与大小，
不能拿指针文本哈希与PNG/MP4内容哈希直接相比。

本次沿用同一前发PNG和前向x/y、UV，分为静态额前域与两侧鬓角域，后帽独立，
只给鬓角域不同z曲面。三轮均能稳定渲染，但中等回退使侧发变钝、交接出现折纹；
小回退保住更多外观，改善却不足。分解、整头、邻角、±15°头骨俯仰和实际并排
MP4都复看后，决定不替换认可版。技术通过与视觉更好是两项判定。

- 已在前发画面中朝眼下的发束，不会因切成另一渲染对象就自然长到耳后。
  仍固定所有x/y并只退z，头面净空会限制内部移动，主要改变轮廓之外的发梢；
  深度变化和UV压缩可能产生折纹、直边或钝尖。
- 分束依据应是发根、束脊、发梢和相邻遮挡的关系。后续若继续，应把根到梢的
  空间曲线、截面、绘画方向与侧视依据一起设计；不是把静态区域继续切碎或增大
  后退量。本次没有实现完整独立束体，也没有证明语义分层方法整体无效。
- 当前正面像素大体保留也不等于零回归。对照两侧斜面和俯仰后，收益不明确就
  留在试验归档，不能因已经做完而晋升到正式资产。只保留代表性对照、候选源码
  和失败原因，其余临时图实际删除，避免再次产生多个“最新”。

### 后脑蓬松度：先诊断大形，别把分层本身当作改善

雷晓后续试验由用户指出“原画蓬松，模型包头”。现有后帽把原图内部笔触映射到
连续椭球上，外缘细发梢并未成为实际后脑轮廓。应先按人物审美文档的问题发现机制
把后脑侧面、后侧、背面和后颈列为主要差距；不能继续围绕耳前微小位移迭代。

- 在帽壳外增加闭合小束，根部、粗细和绘画流向不匹配时会像叶片贴在头上；
  将整壳推成几道波浪也仍是帽壳，且会把笔触拉折。两者不是蓬松度已解决。
- 同一整张后发图旋转叠多层会复制发旋和高光，产生多组小发型，不能用来补全
  缺少的侧面图表。只调整 UV 或增加多边形也不能自动恢复发束关系。
- 独立发束图集可让根到梢曲面获得真实绘画和透明轮廓，但生成的六个束型实际
  映射到十六个曲面后仍出现重复亮根、过碎分组和悬浮梢。本轮静态否决，没有
  因使用了文生图素材或覆盖更多角度而升级 current，也没有声称动态验收通过。
- 图片工具输出的透明 PNG 可能在查看器里显示隐藏 RGB；应核对 alpha，不能
  凭黑色预览判断背景不透明。本次输入和生成图均保留，不重画认可的整头原画。

后续仍需先把冠部—后脑—后颈的主束大小、根部埋入、重叠及末端方向一起设计，
再绑定绘画。少数协调的大束成立之后才加细束；细节更多或差异更大都不是验收标准。

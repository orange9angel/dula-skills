# 人体动作参考的有限重定向实验

当程序步态有正确换脚却缺少肩胯协调时，可以用公开动作数据作为比较基线。
它能提供时间关系，不能自动修复目标身体网格，也不保证重定向后的接触与持械意图。

`scripts/convert_acclaim.py`把ASF/AMC转换为世界关节JSON。当前实现验证了CMU的
XYZ轴、常规root顺序、完全采样AMC格式；不是任意Acclaim方言读取器。单位/fps
由调用者显式给出。本次CMU数据为120Hz，长度缩放0.056444米。

```powershell
python scripts/convert_acclaim.py --asf <source.asf> --amc <source.amc> --fps 120 --scale 0.056444 --output <walk.json>
```

源文件、URL、数据条款、归属与摘要随剧集保存。使用的是
[CMU动作数据库](http://mocap.cs.cmu.edu/)的07/01片段；网站允许各类使用，但不允许
直接转卖动作数据（包括格式转换后）。单位说明见[官方FAQ](http://mocap.cs.cmu.edu/faqs.php)。

`assets/mocap-pose-study.js`为**未通过生产验收的实验适配器**，接受
`THREE,actor,data,getTime,rootAt,start,end,dims`，包装actor.setPose。
episode提供路径与目标骨长，不应复制另一集角色参数后直接投入成片。

当前限制：直线路径、固定腿/臂骨长、source root Z近似单调；用路径距离采样源动作；
窗口外回到原pose，没有自动起停融合。设备/手持物语义与真正支撑锁定尚未完成。
此文件只作为比较实验，成熟制作仍用有限落脚与接触验证流程。

后续反膝修订增加`kneeForward:true`：对当前局部+Z为前方的直立步行，把+Z向量
投影到髋踝轴的垂面作为膝pole。默认false保留旧试验；非直立动作、转向或另一局部
坐标约定不能照搬。骨长恒定不能防反关节：旧33帧双腿66样本有15个膝偏移Z为负，
修订后为0。验收要同时计算`K-H-project(K-H,A-H)`相对角色前向的有符号投影，
再看实际渲染；无符号膝夹角和骨长误差都会漏掉“同一角度弯向反面”。
这一约束只修膝平面，不等于足底锁定、正确摆腿或原画中的膝盖也修好了。

本次发现：

- 缩短stride却直接照搬源髋高，会变成双膝下蹲。髋高须按目标腿长、水平跨距及
  支撑侧伸展一起计算；抬髋后同步更新躯干与肩点。
- 原点高度不是鞋底高度。应从实际鞋网格和当前俯仰估计鞋底，再复核世界接触点。
- 把两脚中较低的一只强制放到地面，可能在摆动脚尚未落地时提前压地；它不等于
  支撑相识别。踝点低且速度高是可疑窗口，需追踪实际接触顶点，不用踝点速度代称滑步。
- 本次骨长误差近机器精度、5次seek像素一致，但接触仍未通过，模型大腿仍有凸块。
  源动作捕捉和数值一致性不能替代实际动作审查。

将动作底稿问题与最终绘画问题分别取证。不要把未修好的动作传播给更多原画。

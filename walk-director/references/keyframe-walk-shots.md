# 2D 关键帧管线的走路镜头：机制、cel 选择与翻车史

来源：cat_leads_e01_sunny_store V1–V11 修订史（剧集 `V1_NOTES.md`）、
rainy_rooftop_cat 三轮翻车（`build-continuous-story-images/references/walk-cycles.md`）、
以及 2026-08-15 cat_leads frame_06 段从 A/B 退役到近/远静帧的定论（见「选型」节）。
代码引用以 `dula-story/episodes/cat_leads_e01_sunny_store/scenes/SunlitStoreSequenceScene.js`
为参照实现，其它 `*SequenceScene.js` 同理。

## 一个 2D 走路镜头的完整定义

四个部分缺一不可：

1. **cel 对**：同一镜头专属的同构图完整画幅图，A/B 两张触地相反相位，
   入库 `assets/action_inbetweens/`。
2. **时间线展开**：`config/keyframe_timeline.json` 中 `[start, end)` 区间展开为
   等间隔 A/B 交替 beats（`transition: "cut"` 硬切），每条带
   `"motionGroup": "<组名>"`。用 `scripts/build_walk_timeline.py` 从
   `config/walk_segments.json` 生成，不要手编。
3. **连续平移运镜**：`"move": "walk_follow"`。
4. **rig 连续性**（有眨眼/口型的镜头）：每帧带 `eyeRig`，第 2 帧起带
   `blinkCarry = at - 组起点`，保持眨眼时钟跨 cel 连续。

## 相机跟随：walk_follow + motionGroup

2D 管线没有 3D 相机，"运镜" = 对源图做 crop 窗采样
（`MOTION_PRESETS` + `_sampleMotion` + `_drawImageCover`）。

`walk_follow` 预设（SunlitStoreSequenceScene.js:46-49）：

```javascript
// 恒定 zoom（避免逐 cel 缩放脉动）+ 整组跨度内匀速 crop 横移。
// 世界向屏幕左滑，向右走的角色读起来才像"真的在往前走"。
walk_follow: { zoom: [1.1, 1.1], panX: [-0.5, 0.5], panY: [0.06, 0.06] },
```

- `panX: [-0.5, 0.5]`：crop 窗从源图左侧匀速移到右侧，画面内容左移 →
  读作角色向右走。**方向必须匹配**：角色向左走时需要一个反向预设
  （`panX: [0.5, -0.5]`），不要复用同一条。
- 恒定 zoom 1.1：顺带把腿部放大约 10%，提高换脚可读性；不要用带 zoom
  起止变化的预设（`push_in` 等），逐 cel 采样会造成缩放脉动。

`motionGroup` 机制（SunlitStoreSequenceScene.js:509-528）：普通帧的 crop 进度按
`(t - frame.at) / frameDuration` 计算——如果每个 cel 子切单独采样，0.31s 一
重启，平移变成往返抖动（V4 当年就是为了躲它把所有走路改成 `static`，结果
"没有跟着移动"）。同组帧共用 `motionGroup` 名后，进度改按**整组跨度**采样，
2.5s 内平移连续。这是"跟着移动"的根。

**铁律：`motionGroup` 帧的 `move` 不许是 `static`。** static + motionGroup =
原地踏步感回归。`validate_walk.py` 把它列为 ERROR。

**但强平移不是必须的**（rainy_rooftop_cat 实证）：其走路段
（3.5–5.0s、29.2–30.2s）是 2-cel @2.7 cel/s + 温和的 `drift_right`
（zoom 1.018→1.035、panX ±0.28），**没有 motionGroup**、逐 cel 重启采样，
观众仍觉得自然。原因：cel 姿态本身承载了运动感（侧景纵深大剪刀换步 +
躯干纹丝不动），温和 drift 只需避免画面完全死住。结论分级：

- 侧景短镜头（≤2s）：cel 姿态到位时，温和 drift 即可，不必上 walk_follow。
- 远景/背影/长镜头（≥2s）：姿态可读性弱，需要 walk_follow 的连续大平移
  强化位移感，必须配 motionGroup。
- 无论哪级，cel 姿态质量都是下限保障——运镜救不了烂姿态（v7），
  好姿态配错运镜也只是浪费（static 埋没问题）。

## 选型：连续换脚 vs 静帧规避（2026-08-15 cat_leads frame_06 段定论）

动手前先判断 cel 对能不能做到像素级一致（v10 工艺：背景 0.00%、
上身 ≤0.2% 像素差）：

- **能锁定** → 按本文件做 A/B 连续换脚。
- **不能锁定**（两张 cel 各自整图重生成，背景在平色区互有重画）→
  **不要硬上 A/B**：亮部平色区的背景互闪 + 下半身整体像素偏移，
  后处理合成救不回来（实测：遮罩贴回先修好背景闪烁、再修小腿断裂、
  最后臀部仍错开——两个独立整图之间做局部合成，接缝只会转移不会消失）。
  改用静帧规避方案：
  - **单帧 + 运镜**：背影走远镜头用 `walk_away` 缓拉远预设
    （`walk_away: { zoom: [1.14, 1.045], panX: [0, 0], panY: [0.1, -0.04] }`，
    人朝远处缩小 = 越走越远）。
  - **近/远两张静帧硬切**（推荐，位移感最强）：同机位生成一张远景 cel
    （角色缩小至约 1/3、走到下一段路上、仍在原行走线；参考实现
    `cat_leads_e01_sunny_store/tools/gen_frame06_far.sh`），段中硬切，
    近景拍 walk_away、远景拍 pull_out。两张图是不同构图的完整镜头，
    不存在拼接缝问题。
  - 段落退役后记得把 `walk_segments.json` 里对应 segment 删掉并注释，
    防止 `build_walk_timeline.py` 重跑时把 A/B beats 铺回来。

## cel 选择（"关键帧效果一般"的对策）

按踩坑时间顺序的教训：

1. **每镜头专属，不跨构图复用。** V1 三段走路共用一张侧景换步图，背影/正面
   镜头切入它时构图跳变。每段走路必须有自己构图的 cel 对。
2. **完整画幅，不要矩形羽化贴回。** V4 把生成的腿部羽化贴回基帧，贴回区域
   带进裙子/手/地面色块，A/B 切换时一块矩形在闪。B 帧必须是整图重生成
   （基帧作构图/角色锁，旧 B 帧只作腿相参考）。
3. **等幅触地互换（触地A ↔ 触地B），不用下压/过渡/上提中间姿势。** V3 的
   8-cel 完整步态在 crop 运镜下被废弃：中间姿势带来身体起伏，且与平移
   采样冲突。2-cel 等幅触地互换在 ≤2.5s 镜头 + 连续平移下成立
   （walk-cycles.md 2026-08 补充）。**更长镜头（>2.5s）不要硬用 2-cel**，
   按 walk-cycles.md 的分级表上 3-4 cel。
4. **相位差必须全尺寸可读；背影的可读性来自纵深，不是横向分腿。**
   验收时把 A/B 并排全尺寸看：哪条腿在前承重、哪只脚跟离地，必须一眼
   可分。背影镜头正确的可读性来源是**前后纵深错位 + 后脚脚跟抬起（蹬
   地相）+ 重心倾斜**；横向分开是错误方向——脚分太开读作叉腿站立而非
   行走（v7 实测翻车：脚心横向分离 1.3 鞋宽，相位清晰但姿态难看、无移
   动感）。自然/少女感步态双脚都落在身体中线附近（横向 ≤ 半只鞋宽）。
5. **鞋尖朝行走方向。** 强制"相反触地相"时模型容易把脚画反（像反装），
   prompt 里逐字写清每条腿位置和鞋尖朝向（详见 walk-cycles.md 生成顺序）。
6. **地面投影随脚反相。** 平色/写实风格里角色的落地影是烘焙进 cel 的：
   A/B 换腿时影子的脚部形状必须跟着反相，否则腿在走、影子不动。prompt
   里写明"地面影子的脚部轮廓跟随触地脚位置"，验收时和腿一起核对。
7. **尺寸与基帧一致。** 不同尺寸的 cel 交替会造成取景跳动；
   `validate_walk.py` 会检查组内 PNG 尺寸一致。

## 换腿 prompt 控制（2-cel 全幅 B 帧生成）

通用生成流程（参考链、provider、锁定区贴回）见
`build-continuous-story-images/references/walk-cycles.md`；本节是走路换腿
**专用的 prompt 写法**，来自 cat_leads_e01 V3–V5 的定稿实践
（`generation_prompts.md` 有逐帧原文）。

1. **参考图分工**：基帧 = 构图锁 + 角色锁；旧 B 帧或姿势参考图 = **只作腿相
   参考**。不要让腿相参考图把构图也带走。
2. **一律用 viewer（画面）视角逐字写腿位**，不要写"她的左腿/右腿"——模型
   的左右会镜像混乱。V3 的腿序锚定问题就是靠"画面左髋腿明显交叉至右前鞋、
   右髋腿接左后鞋"这种写法解决的。
3. **等幅反相的写法**：明确要求"保留同一前后落脚点，两脚交换；双脚落地，
   步幅相同"。等幅是 A/B 交替不跳构图的前提。
4. **可量化验收（纵深而非横向）**：背影镜头写明"两脚前后纵深错位约一只
   脚长；后脚脚跟明显抬起、前脚掌撑地"，横向则要求"双脚落在身体中线附近、
   不超过半只鞋宽"。验收时量纵深错位和脚跟抬起，**不要**量横向开度——
   横向越宽越像叉腿站桩（v7 教训）。
5. **锁死上半身——包括胯、裙摆、手臂、头发，零例外。** 2-cel 高速交替
   （≥2.4 cel/s）下，胯部/裙摆/手臂在 A/B 间的任何微动都读作"扭"
   （v9 实测：允许"胯部随承重腿轻微倾斜"后，上身像素差 20%，观众直接
   反馈"像扭、不如上一版自然"；对照 v8 上身差 1.6% 就自然）。prompt 里
   不要给任何胯部倾斜的许可；重心转移只靠腿脚表达。模型常顺便改
   姿态，交替时上身会跳。
6. **禁忌**：不要拿"中立站姿"当 B 帧（frame_11 早期废案，站直了相位差为
   零）；不要单脚抬起的腾空姿势（V4 起弃用抬腿/下压/上提）；背影写
   "远脚/近脚"，不写左右腿。
7. **渲染精度要显式锁定**（v8 教训）：局部编辑的重绘区域会比基帧粗糙——
   轮廓带笔触/锯齿、皮肤出现红晕斑块、影子被重画成别的颜色。prompt 里
   必须逐字写明：重绘区域轮廓 razor-clean 无笔触无噪点、皮肤单色平涂
   +一层与基帧同款的干净阴影、**地面影子沿用基帧的平色（点名颜色，如
   薰衣草色），仅形状跟随脚位**。不点名颜色，模型会自己换一种（v8 的
   亮蓝色影子就是这么来的）。
8. **支撑脚要逐像素锚定**（v10→v11 教训）：contact↔passing 循环里，
   passing 帧的支撑脚若与 contact 帧差几到十几像素，在连续平移的地面
   上每次切换都"瞬移"一下，观众看到的是**小腿周围一块矩形区域在抖**
   （支撑脚区实测差 10.8% 即可感知）。生成侧 prompt 锚定（"支撑脚逐像素
   一致"）会把摆动幅度一起压死（v12 实测：支撑 2.3% 但摆动 27%→3.6%），
   **标准工艺是后处理锚定**：生成大摆幅 passing 后，用
   `scripts/anchor_support_foot.py` 把 contact 帧的支撑脚+接触影子经
   羽化小框贴入 passing。贴框只能罩住支撑鞋+脚下接触影——碰到摆动脚
   的影子区会把两种影子形状混成平色风格下刺眼的模糊团（v3 教训，
   框收窄后消失）。验收：支撑脚区像素差 <3%，摆动区保持大差异。

实测定稿 prompt 骨架（按机位三选一，填入 viewer 视角的腿位描述）：

| 机位 | 骨架 |
|------|------|
| 侧面远景 | 「侧面等幅反相触地：保留同一前后落脚点，画面左髋腿明显交叉至右前鞋、右髋腿接左后鞋；双脚落地，步幅相同；上半身与构图不变」 |
| 背影远景 | 「背面等幅反相触地：双脚贴在身体中线附近（横向 ≤ 半只鞋宽）；远侧脚向前迈一小步全脚掌落地承重 ↔ 近侧脚在前承重，另一脚留在后方脚跟明显抬起、前脚掌撑地（蹬地相）；前后纵深错位约一只脚长；鞋轴沿道路透视；上半身与构图不变」 |
| 正面走近 | 「等幅反相触地：画面右腿前伸 ↔ 画面左腿前伸；前伸大腿大小一致，双脚落地；上半身固定，不使用中立站姿」 |

实测记录（2026-08-13 walk_skill_test，frame_06 背影）：

- **v7（翻车）**：初版背面骨架把可读性量化成"脚心横向分离 ≥ 一只鞋宽"，
  一次 roll 得到相位清晰的 A/B（分离 1.3 鞋宽），但观众反馈**腿分太开、
  像叉腿站桩、无少女感、无移动感**。结论：可读性 ≠ 横向开度；修正为
  纵深错位 + 脚跟蹬地（见上文第 4 条与骨架表）。v7 废弃。
- **v8（姿态修正，验收通过但有 fidelity 缺陷）**：按新骨架（双脚贴中线
  ≤半鞋宽、纵深错位一脚长、后脚脚跟抬起蹬地）重新生成，3.2 cel/s +
  全幅平移下动态抽帧换脚可读、姿态自然有推进感。这次"edit image 1、
  其余逐像素不变"的写法让 codex 走了真局部编辑——A/B 间背景 0.00%
  像素变化。**但**重绘的腿部渲染精度降级：轮廓带笔触锯齿、膝盖红晕
  斑块、地面影子被换成饱和蓝色（观众反馈"边缘粗糙、光线不自然"）。
- **v9（精度锁修正，但引入新翻车）**：边缘与影子颜色修复，但 prompt
  给了"胯部可随承重腿轻微倾斜"的许可 → 上身像素差 20%，裙摆/胯/手臂
  在 A/B 间微动，观众反馈"像扭、不如 v8 自然"。教训固化为第 5 条
  （胯裙手臂像素级锁定，零倾斜许可）。
- **v10（合并修正，定稿）**：v8 姿态语义 + 胯/裙摆/躯干/手臂/头发逐像素
  锁定（明确"只允许膝盖以下有差异"）+ 渲染精度锁 + 影子点名色。实测
  A/B：躯干裙摆 0.20%、背景 0.00% 像素变化（扭的结构性消除），腿部差异
  6.9% 集中在脚跟起落；边缘干净、影子薰衣草色正确。动态抽帧换脚可读、
  自然小步快走感。**三代结论：姿态可读性（纵深+蹬地）、上身零晃动、
  渲染精度、影子颜色，四个约束必须同时写进 prompt，少一条就翻车。**
  另注意腰部锁定让腿部差异变小，需在"再弱化就不可读"的边界上停手。
- **v11（治"抖动"，定稿）**：v10 的脚跟微抬小动作在 3.2 cel/s 下读作腿边
  振动（腿部差仅 6.9%，小动作×高频=振感；且测试段没加程序化环境层，
  世界像素冻结让每次切换变成刺眼硬跳）。改为 rainy 实证配方：
  **contact ↔ passing 2-cel**（passing = 摆动腿屈膝抬起、脚明显离地，
  每次切换 ~20% 大幅变化）+ 2.7 cel/s + 段落补 cloudDrift/dappleSway
  环境层掩盖切换。躯干锁定/精度锁/影子色全部保持。已知边界：同一
  passing 意味着总是同一条腿在抬，>3s 长段若看出单腿重复，升级为
  4-cel（contact→passing→contact→passing2）；反相触地 B 不可靠
  （v11 实测模型产出与 A 同相），4-cel 的第二张 passing 比反相触地
  好生成（延续"从 passing 继续走半步"的模型可靠性排序）。
- **v12→v8（治"支撑脚瞬移"与"影子翻转"，定稿工艺）**：v11 后观众仍见
  "小腿周围矩形区域抖动"，分层排查（方法论见 verify-walk-shots.md）定位
  两个叠加源：支撑脚落点瞬移（10.8%）+ **大投影形状在 cel 间翻转**
  （切换帧地面区 23.8%，源图影子带 55.7%——cat_leads 正片双脚落地所以
  影子恒定不抖；passing 抬脚必然动影子，这是接触↔抬脚换相的固有代价）。
  生成侧锚定（v12）会把摆幅一起压死（支撑 2.3% 但摆动 27%→3.6%）；
  定稿为**后处理两段合成**（`scripts/anchor_support_foot.py`）：
  ① 窄框把 contact 的支撑鞋+接触影贴入 passing；② 地面带统一——脚以下
  带区内非深色像素全部贴成 contact 的（两 cel 共享同一片影子），深色
  袜鞋连其柔影用**膨胀排除**保留。两个坑：贴框碰摆动脚影子会混出模糊
  团（v3）；排除不膨胀会把摆动脚影子切半、留下白渍（v7）。
- 尺寸锁定生效：v7/v8 均 1672×940 与基帧逐像素一致。
- **代价要量化记录**：全幅再生成必然带整图噪声。v7 对 A/B 间背景变化
  像素约 22%（mean diff 28），约为 v6 对（约 10–13%，mean 13–15）的两倍。
  静态抽帧不可感知、2 cel/s + 平移下通常可接受；若观众反馈背景微闪，
  缓解方向：prompt 追加"平色区域逐像素保持一致"、降低光斑形状差异，
  或退回局部编辑+锁定区贴回（贴回区必须只含腿部，牢记 V5 矩形闪教训）。

速率经验值（cat_leads V11 定型）：

| 镜头 | 速率 | 驻留 | 说明 |
|------|------|------|------|
| 远景侧景 / 背影 | 3.2 cel/s | 0.3125s | 换脚频率高一点才读得出"在走" |
| 正面走近（中景） | 2.4 cel/s | 0.4s | 近景脸部占比大，切换太快显闪 |

通用下限：每张 cel 驻留 ≥0.15s，低于 0.1s 闪成噪点（walk-cycles.md）。

## 步态风格（2D）：少女感 vs 老奶奶蹒跚

2D 管线的"走相"由三层叠加，三层要一起改，只改一层会露馅：

1. **cel 内容（prompt 层）**——姿态本身。写在换腿 prompt 里：
   - 少女感：正常偏大步幅、支撑腿挺直、手臂自然摆动、抬头、身体重心高。
   - 老奶奶蹒跚：**小步幅**（前后脚只错开半只鞋）、拖步（鞋底几乎贴地，
     不画抬脚）、驼背前倾、手可扶膝/拄杖、重心低。
   - 蹒跚的 A/B 相位差仍须可读（规则不变），只是步幅本身画小；分离度
     要求可放宽为"至少半只鞋宽"。
2. **rate（步频层）**——cel/s 就是视觉步频。3.2 是轻快步；老奶奶给
   1.6–2.0 cel/s（驻留 0.5s 左右，`validate_walk.py` 对 >0.5s 只 WARNING，
   蹒跚镜头属预期内）。步频下来了，步幅画小才有意义。
3. **平移速度（运镜层）**——`walk_follow` 的 panX 总量（[-0.5, 0.5]，即
   整段镜头扫过一个源图宽度）对应"这段路走了多远"。慢步态必须配慢平移，
   否则脚在挪、地在飞 = 滑步感。预设不是一个常量：为慢步态在剧集场景里
   加一条自定义预设即可，例如
   `walk_follow_slow: { zoom: [1.1, 1.1], panX: [-0.25, 0.25], panY: [0.06, 0.06] }`，
   然后在 `walk_segments.json` 里把该段的 `move` 指过去。

经验对齐公式：平移扫过的地面宽度 ÷ 镜头时长 ≈ 步幅(画面) × 步频(rate/2 步/s
量级)。不用精确，量级不冲突即可；冲突肉眼立见。

**已知局限**：`build_walk_timeline.py` 的 beats 是等间隔交替。蹒跚/跛脚
常见的"一脚重一脚轻"不对称节奏（A 驻留长、B 驻留短）目前要手编时间线；
如成高频需求，再给 `walk_segments.json` 加 cel 驻留权重字段。

## 设计维度清单（开拍前过一遍）

走路镜头不只是"步态 + 平移"。按层从里到外过一遍：

| 维度 | 2D 管线的承担者 | 要点 |
|------|----------------|------|
| 步态 | cel + rate + pan 速度 | 见「步态风格」节，三层一起改 |
| 相对运动 | `walk_follow` pan | 方向匹配行走方向；单张图无视差，长距离行走远景不动会显假，超 ~3s 考虑分层或切镜 |
| 光影 | 程序化层 + cel 烘焙 | 背景光斑/云画在**源图空间**、随平移一起走（`_renderShotSource` 注释明确如此），白送；**角色身上的光影烘焙在 cel 里不会随移动变化**——走过树荫/光斑交界的长镜头要么接受、要么做 cel 变体。落地影随脚反相见「cel 选择」第 6 条 |
| 声画同步 | 脚步声 SFX（归 direct-episode-audio） | 每 2 张 cel = 一步，footsteps 的步点密度随 rate 走；步态变了脚步声的材质/体重感也要变（老奶奶 = 拖步声）；本 skill 只负责在分段定稿时把 rate/时长交给音频侧 |
| 起止衔接 | smoothstep + 边界帧 | 组进度的 smoothstep 已给平移缓入缓出；切出时人物在画面中的位置要与下一镜头连续，急停镜头最后接一张站定帧 |
| 视线/表情 | cel 烘焙 + eyeRig | 走路时看谁（猫/店门）画进 cel；眨眼跨 cel 已有 blinkCarry；边走边转头需要额外 cel 变体，成本另算 |
| 地形 | cel + 预设 panY | 当前预设纯水平平移；上下坡/台阶要给预设加 panY 分量，姿态（上坡前倾/下坡后仰）画进 cel |
| 风 | 程序化层优先 | 见下节 |

## 风的定位

需要考虑，但它是**环境连续性**问题，不是走路专属问题。判断顺序：

1. 同集其它镜头有风动（云飘、树晃、蒸汽斜）而走路镜头里头发裙摆纹丝不动，
   会显死——**低成本解法是让程序化环境层带风感**（cloudDrift/dappleSway
   已随平移走），走路镜头直接受益，不用动 cel。
2. **不要把发丝/裙摆摆动做成 A/B 两张 cel 的差异**：既干扰换腿可读性，
   又让交替时头发跳。风的动效要么程序化、要么不做。
3. 只有**叙事性强风**（顶风难行、风吹起裙摆/伞）才画进 cel 姿态本身
   （被吹起的裙摆就是姿态的一部分，A/B 两张保持一致）；这已超出走路
   范畴，按 scene-designer 的程序化层 + build-continuous-story-images
   的姿态变体处理。

## 翻车对照表

| 症状 | 根因 | 修法 |
|------|------|------|
| 走路时场景不跟人动 | `move: "static"`（V4 回退遗留） | 改 `walk_follow` + `motionGroup` |
| 平移往返抖动 | 逐 cel 重启 crop 采样 | `motionGroup` 整组采样 |
| 切走路镜头构图跳变 | 跨镜头复用同一张换步图 | 每镜头专属 cel 对 |
| A/B 切换一块矩形在闪 | 腿部羽化贴回基帧 | 全幅重生成 B 帧 |
| 像原地踏步 | 画面不动（static），不只是 cel 少 | 连续平移；必要时加 cel |
| 换腿看不出来 | 相位差太小（背影高发） | 纵深错位 + 脚跟蹬地，**不是**横向分腿 |
| 走路像叉腿站桩、无移动感 | 把可读性做成了横向分腿；双脚都平放无推进线索 | 横向贴中线 ≤半鞋宽；后脚脚跟抬起蹬地（v7 教训） |
| 走路像"扭"、不如上一版自然 | 胯/裙摆/手臂在 A/B 间微动（给了胯部倾斜许可） | 上半身含胯裙摆像素级锁定，重心只靠腿脚表达（v9 教训） |
| 腿边画面抖动/振感 | 小动作（脚跟微抬）× 高频切换 + 世界像素冻结，每次换 cel 是刺眼的局部硬跳 | 大步幅 contact↔passing（脚明显离地）+ 降到 ~2.7 cel/s + 程序化环境层让背景持续呼吸（v10→v11 教训，rainy 配方实证） |
| 3-cel 想覆盖全步态 | 反相触地 B 生成困难（v11 实测：prompt 要求反相，产出仍与 A 同相，A↔B 仅 5.2% 像素差） | 背影反相触地不可靠；用 contact↔passing 2-cel 或生成第二张 passing 凑 4-cel |
| 小腿周围矩形区域抖动 | 支撑脚落点在 cel 间瞬移（独立生成的两张图支撑脚差几到十几像素），在连续平移的地面上每切换必跳 | prompt 锚定支撑脚逐像素一致（第 8 条）；残余用逐 cel 微重启/步顿 impulse 掩盖（rainy 歪打正着的机制） |
| 整图再生 A/B 在平色背景区互闪 | 两张 cel 各自整图重生成，光斑/路面等平色区被重画；观众盯着脚看，紧邻小腿的背景闪烁最刺眼（cat_leads frame_06 v6 对，2026-08-15） | 生成侧锁到背景 0.00%（v10 工艺）；锁不住就不要做连续动作，改静帧 walk_away / 近远两拍（见「选型」节） |
| 遮罩贴回修复后腿部/臀部断裂错开 | B 图下半身相对 A 整体偏移（实测 -3px），局部贴回把错位的腿接到 A 的躯干上；对齐后再发现遮罩上沿又错开——接缝只会转移 | 两个独立整图之间不做局部合成；接受像素差或改静帧方案（同上） |
| 换腿后腿部边缘粗糙、光影不对 | 局部编辑重绘区渲染精度降级，影子被换成新颜色 | prompt 显式锁渲染精度 + 点名影子颜色（第 7 条，v8 教训） |
| 脚像反装 | 相反相位时鞋尖方向拧反 | prompt 逐字写鞋尖朝向 |
| 走得慢但地面飞快滑过（滑步感） | 步频/步幅改了，平移速度没跟上 | 慢步态配小 panX 的自定义预设（见「步态风格」节） |
| 蹒跚走看起来还是少女步 | 只调了 rate，cel 里步幅/驼背没画出来 | 三层（prompt/rate/平移）一起改 |
| 眨眼在换 cel 时跳变 | 缺 `blinkCarry`，眨眼时钟重置 | 组内继承 eyeRig + blinkCarry |
| 工具重跑把成果回退 | 剧集一次性脚本硬编码旧策略 | 用 `build_walk_timeline.py` + `walk_segments.json` 可重放 |

# 以可复用动作资产控制生成成本

用于用户授权agent选择效果与成本平衡方案的角色动画。当前优先路线是：可靠3D
动作与空间底稿，已认可的二维角色设计，少量受约束补画，以及确定性合成。
这是一套制作决策，不能声称已证明全局最优或任意新角色全自动达标。

## 按资产制作，不按影片每帧重新生成

| 内容 | 责任层 | 复用边界 |
|---|---|---|
| 路径、重心、肩胯、落脚、手与道具接触 | 3D动作底稿与接触控制 | 相同比例和动作意图；换比例须重新验脚点 |
| 脸型、发型、人体轮廓、衣甲画形 | 经审查的角色原画与clean plate | 同朝向的小幅动作可复用；转面和新可见面需补画 |
| 同一视角下的小幅头身运动 | 底稿驱动的有限二维配准与形变 | 保持人体连接和支撑；超过原画可表达范围就回到补画 |
| 缺失的过腿、极值、转面或遮挡变化 | 局部编辑或受姿态约束的新原画 | 只生成明确缺口，串回动作验证后才纳入资产 |
| 刚性盾、武器、护甲及战损 | 固定几何/画形、握点与剧情状态 | 不随整人物生成随机改设计；透视缩短与尺寸漂移分开 |
| 已认可场景与动态效果 | 原场景合成；粒子系统 | 延续既有场景；火、烟、招式、火把执行粒子规则 |

身体造型可突破旧代理模型，但接触、左右肢体身份和道具状态不得靠画面猜测。
不要把原模型的错误大腿轮廓锁进最终画形；也不要把原画与模型形状不同后的
稠密像素对应，当成能自动生成中间画的能力。

## 一个动作资产的制作顺序

1. **先固定表演和底稿。** 选一个可比较的周期，检查换脚、前后遮挡、膝向、重心
   和肩胯关系。世界落脚尚未验证时明确写出；不能因数据来自真人就跳过检查。
2. **锁定人物与装备设计。** 记录同一视角的整头、衣甲轮廓、比例、持物和战损。
   脸与身体精修、锚点和蒙版由agent完成，不要求用户逐角色协助校形。
3. **先用现有原画。** 验证同机位胸身、头颈与整体运动。画形在身体坐标稳定，
   头、胸、胯按支撑交换联动；不能以冻结头部取得零抖动指标。
4. **按可见缺口补画。** 给每张候选声明前后锚画、目标关节/遮挡与不可变区域。
   优先编辑缺失区域；整人物新画必须证明相比现有原画有净收益。
5. **回到完整动作验收。** 同画幅、周期、速度对照，检查接缝、脚、手、装备与
   身体起伏。关键点处更顺而其他地方跳变，不能算整段升级。
6. **通过后才接入实际场景。** 配合根位移、接触阴影、前景遮挡与机位复验，
   再扩展起停、转身与近景。未通过的动作资产不批量覆盖整片。

## 成本控制

- 预算单位是“角色 × 视角 × 动作周期/表情组”，不是视频帧数。一个通过的走路
  周期可重复播放和在允许范围内重定时，无须重复生成同一内容。
- 8、12或16张都是候选规模，不是自然度等级。完整换脚、曝光和相邻形体关系
  比格数优先。多宫格节省调用，但同样输出尺寸下每格分辨率下降。
- 每轮只生成能验证一个缺口的小批候选。记录调用数、保存原图与提示词、适配
  时间和最终采用比例。没收益就否决或改变约束，不不断加图摊薄失败。
- 输入参考、输出尺寸、质量和返修都会影响API成本。内置工具未返回usage/费用
  时记unknown，不能拿公开API单价冒充订阅实际扣费。

## 已执行的边界与后续工作

`scripts/drive_cel_body.py`已实现限定机位下的clean plate重用、显式遮挡蒙版、
腰部有限配准、3D肩胯投影及共同身体运动，输出分层、逐帧对照与报告。
`beforeFrames`可指定同画幅的上一版PNG序列作实际同时间对照；各cel可用
`joinUnderlay`覆盖默认窄接缝补底范围。配置由agent适配，未实现自动人体分割。

2026-10-24试片：胸廓画形跳变减少、头区不再锁屏；新增四张整人物补画后，
仍出现不合适的摆臂幅度和腰甲变化，12格候选被否决。一次生成四张本身不是
效率收益；实际采用质量才是。下一步的刚性装备绑定、局部受约束过渡、世界
接触和多视角表情仍需独立实现与验证，不能写成已完成的通用生产线。

相关执行入口与失败证据要求见[混合路线实验](hybrid-character-routes.md)、
[角色注意力巡检](../../character-attention-review/SKILL.md)及
[步态制作](../../walk-director/SKILL.md)。

## 腰胯连续画形与有限体积投影

后续用户仍指出胯部抖动和纸片感，R3不再作为推荐方案。局部胸身稳定没有解决
八张腰胯画形切换；重定向又保留了胸部旋转，却丢掉源骨盆方向。先修动作参考，
再让同一腰胯画形随骨盆运动，避免继续以背景光影掩盖身体自身的问题。

`scripts/drive_cel_volumes.py`是**限定机位的实验工具**：读取`drive_cel_body.py`
导出的`full_body.png`、各cel的`*_near.png`/`*_far.png`，以显式蒙版取腿层；
由捕获的胸/胯角度分别驱动浅曲面投影，腰腹作连续过渡。`depthProfile`每行是
`[y,centerX,radius,depth]`，单位为原画像素；这是有界的2.5D近似，不是人物三维重建。
腿和手臂仍保留已有原画姿势，不能据此宣称自动中间画、自然接地或转面已解决。

```powershell
python scripts/drive_cel_body.py --episode <episode> --config config/walk_layers.json
python scripts/drive_cel_volumes.py --episode <episode> --config config/walk_volumes.json
```

第二份配置以`layersConfig`引用第一份，另提供同画幅`beforeFrames`、`output`、
`depthProfile`、`chestY/pelvisY/pivot`、`followEndY/footLockY`、身体及腿层过渡区、
大腿根配准区和四个角度增益。当前示例在S1E2的`config/walk_cel_r6_volumes.json`；
换角色需重新定蒙版与像素坐标，不复制参数当自动适配。源捕获必须显式启用
[骨盆方向保留](../../walk-director/references/mocap-study.md)。

本轮有用的修正：

- 大腿根配准只读取腿层，不能把武器、手臂或原腰甲算进宽度。
  **后续R6已否决R5的`rootProfile:per_row`作为自然人体修法**：把双腿逐行压到
  同一横截面，会缩掉大腿中段并弯曲原股骨走向。R5跨步原画的部分行宽仅剩
  原稿约70%，此前“接缝更连续”的观察漏掉了这项退步；不能继续推荐该配置。
- 相同姿势下只需调整腿根挂接时，可选`rootProfile:translate`：根据根部中心
  作横向位移，向膝前线性减到0，保留每行原有宽度与直线走向，不做逐行缩放。
  `rootSampleY`应在腿根而非跨步中段，`rootBlendEndY`放在受保护膝区之前。
  这是限定机位的线性剪切，不是通用骨骼变形或对任意原画比例的自动修复。
- `bodySupportY:[start,end]`可让底图裤料边缘随腿层支撑收回，防止缩小修型范围后
  旧底图留下悬空裤边；起点必须低于所有硬甲尖端。先保全腿的体积和关节走向，
  再修局部接合，不靠挤细腿来迁就底图。
- 武器蒙版须包含暗色杆身和描边。按紫色筛选会漏掉暗边，移到独立运动层后
  原来被叠盖的缺口才暴露。`weaponOverrides`接受整轮廓多边形。
- 相邻部件运动不同会露出此前被遮住的区域。当前`clothUnderlayY`仅按同一腿行
  的暗色裤料补小范围遮挡底色，不会生成新衣褶或轮廓；明显露新面须补画。
- 报告中的投影误差、逆映射残差只检验数值执行，不能用作动作自然度分数。
  `occupiedRowWidthRatio`比较配准前后实际alpha覆盖像素数，可暴露意外挤压，
  但它是双腿占用行宽，不是解剖截面、三维体积或自然度。R6各原画平均约1，
  同时实际复看了完整人物和33帧大腿序列，才确认本次面条腿退步已减轻。

用`--frames 0 5 19`可先渲染有代表性的局部候选；报告保存`selectedFrames`，不能
把局部试跑说成完整周期。该例先否决了只缩短混合范围的接缝折角候选，再全周期
验证线性配准；原姿态控制、上身区域和小腿下段均保持。各角度仍需独立适配。

本试片腰甲换形减少，但原8格的摆臂、腿势和武器尺寸仍跳变；尚未完成实际场景
接触和正常速度观感验收。共享工具可复用，不代表这条路线已通过生产验收。

R6交付后，用户于2026-10-24反馈“基本可以了”。该固定朝向步态已获得用户的
基本认可，后续制作以R6姿势与形体为比较基线。该反馈与上述agent观察范围分别
保存；不能继续把R5当推荐配置，也不能扩大成跨视角、接地或整片自动通过。

## 头部不能继续共用胸胯形变场

R6之后用户指出颈部以上仍像折纸人偶，头部变化缺少立体感。此前对腿形与共同
起伏的检查漏掉了头、耳、后脑相对领口的空间关系；“头没有冻结”“原画身份稳定”
都不能证明转动成立。旧头部两点距离变化仅约2%，也不能据此否认明显纸片感。

`scripts/rigid_cel_head.py`通过`drive_cel_volumes.py`的可选`head`配置接入：

- 从[动作转换器](../../walk-director/references/mocap-study.md)保留的世界旋转矩阵，
  按捕获的`sourceFrame`做SLERP，再拟合周期旋转向量。源坐标轴、演员朝向和摄影
  基向量必须显式转换。位置骨架不能恢复绕骨轴的头部转动，不能从颈—头连线猜yaw。
- 根据本机位的`depthLandmarks:[x,y,z]`、头部蒙版、颈根pivot和相机焦距建立
  **单视角深度表面**。全部头部点共用一个三维刚性变换，透视投影保留原画外观。
  这是有限2.5D投影，不是闭合头模，也没有新露面的纹理、重新光照或自遮挡求解。
- 深度按本视图中的面部正面、侧面、耳与后发关系绘制。接近侧面的鼻尖未必最靠近
  相机，不可机械地把鼻尖设为最大Z。深度、头型、蒙版均由agent适配，不能宣称
  已实现任意新角色自动建模。
- 颈根跟随原身体锚点，头部朝向独立；原领口在前，头颈和后发在后。`underlapPx`
  仅向已有不透明领口内延展颈部隐藏像素，不向脸发外轮廓膨胀。查耳根、下巴、后颈、
  后发与领口，防止断颈、旧头残留、紫色领口被误带到皮肤。
- 先观察原幅度再选`rotationGain`，不能把头冻住。试验中原源动作点头偏大，保留
  相位关系而缩小俯仰，重新观察完整周期；不另加任意正弦“生命感”。

示例配置：S1E2 `config/walk_cel_r7_head.json`。`head`还包含`motionFile`、`bone`、
`sourceAxes`（三轴各为±1）、`harmonics`、`pivotDepth`、`anchor`、`focalPx`、
`maskPolygons`、`depthRange`和可选`maxRotationDegrees`（默认8°）。配置缺省不改变
旧渲染路径；超出角度限制或投影折叠时停止，需要补新角度原画而非继续拉伸。

执行检查区分三类：零姿态回到原图、三维点间距离与旋转正交性检查刚性；同一姿态
下与平面投影比较检查深度是否实际参与；完整头颈帧列与正常观看检查观感。R7关键点
相对平面最大视差约1像素，属于小幅收益，不能把数值非零写成纸片感已根治。
仅观察解码帧列时必须如实记录。头发仍作为同一刚性表面运动，独立发梢跟随未完成。

本次参考了[头部体块与角度教学](https://www.proko.com/course-lesson/how-to-draw-the-head-from-any-angle/)
的文字笔记，以及[步行与头肩错时教学](https://www.animationmentor.com/blog/tutorial-animating-human-walk-cycle/)
的文字说明；没有观看教学视频。实际应用限于面部正侧面关系和独立头肩运动，
不把阅读经历当作制作验收。R7仍为待用户观感判断的同机位试片，未替换正片。

后续用户认可R7“差不多了”，要求进入正片、整体细节以后再调。以这次实际授权
推进整集，不重复索要技术路线批准。`drive_cel_volumes.py`的可选`rgbaDirectory`
把相同合成结果导出透明帧；`assets/baked-cel-clip.js`可接到`cel-stage`，按路径距离
选择已审帧，接受原画锚点和各帧脚下影/持物位置。不要给已烘焙的头颈再叠一遍
同类形变。`cycleTravel`和`place.distance`为原画像素尺度，场景路径距离须除以
显示比例；`anchor`及各帧landmarks使用原画坐标，x/y为场景中的锚点位置。
它不是足底锁定证明；RGBA图中相连的双脚可能只得到一个阴影分量，不能用其
数组索引当稳定左右脚身份。

接正片时检查起停边界：走路后立即换回旧版站姿会突然改体型和头向。可将末段
步相安排在收脚画并保持到切镜；后退复用反向相位时明确这是有限后退步态，不是
背面新视角或通用退行动捕。新生成后脑/背面不能凭镜像现有正脸代替。

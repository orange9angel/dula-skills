# 按区域、按关键时刻使用生成原画

适用：3D已能提供动作/接触，算法绘制的脸、头发或衣褶达不到要求，而整人物生成
会丢失步相、身份或道具状态。已有有限视角的曲面投影与对照工具；不是通用自动修画器。

## 分工依据

按可见缺陷及控制需求划分区域，不把“规则形状归3D、不规则形状归生成”作为绝对
分类。脸和头发也有必须保持的结构；复杂形状不必全交给生成。优先保留已通过的
3D腿部、根位移、手物接触、硬质道具状态，用生成原画提升确定需要改善的画面。

| 部分 | 结构与时序的来源 | 可生成的内容 |
|---|---|---|
| 步态/肢体 | 原3D骨架、左右腿身份、支撑与根轨迹 | 经验证的衣褶、甲片画味，不能重新决定换腿 |
| 脸部 | 角色身份、头部角度、视线/表情/口型时点 | 按相应视角生成整脸或头颈原画，保留相互比例 |
| 头发/披风 | 根部连接、整体摆动、前后遮挡 | 发束轮廓、发梢、褶皱与局部关键画 |
| 场景 | 可交互区域、摄影、人物接触与投影 | 已接受的绘画底图、局部纹理/不规则形体 |
| 火焰/烟/招式 | 粒子系统、世界锚点及剧情事件 | 不用生成静态火图替代粒子 |

## 空间区域与时间复用

- 区域可以是不规则alpha蒙版，包含脸颊、发束、衣褶或外轮廓，并随物体运动。
  提供整头/整人和相邻帧作为上下文，最终只合成目标区域；不要独立生成互不约束的五官。
- 先区分“表面细节修画”与“改变轮廓的原画”。前者可尝试UV/表面投影，后者还须
  清除旧轮廓、补露出背景并更新遮挡及阴影，具体接入见[dula-integration.md](dula-integration.md)。
- 同角度、小形变片段优先复用已验收的原画，按表面坐标/控制点传播。朝向明显改变、
  原来被挡住的部分露出、表情极值或轮廓拓扑改变时补关键画；不要无限拉伸同一贴片。
- 3D提供ID/深度/运动信息的条件较好，但当前尚无通用多角度导出及按区域传播链。
  最小试片只补本镜头所需通道；3D关节JSON和矩形贴回工具不能冒充已经实现该能力。
- 蒙版外保留原渲染结果；蒙版内仍检查角色一致性、局部线宽/光色及跨帧稳定性。
  羽化不能修复透视错误、错误动作或身份漂移。

## 效率与验证

可复用原画、局部返修及明确的生成范围有机会减少整帧重生成的浪费；前期分层、
绑定、遮挡和合成成本会增加。目标区域面积小，不代表工具按该面积扣费，也不保证
token更少。记录实际调用数、返回尺寸、可用帧数、复用时长和人工/程序处理时间。

## 已实现：有限视角的曲面作画

共享模块 [projected-region-paint.js](../assets/projected-region-paint.js) 在参考姿势下给
原头部网格烘焙投影UV和朝向权重，绘画随原网格/子对象变换运动，保留原深度遮挡、
投影及身体动作。它不改头型轮廓，也不自动提供新的表情、口型或未画出的背面。
当前验证是程序角色的刚性头部与变换驱动发束；蒙皮参考姿势及CPU逐顶点变形未验证。

```js
const paint=createProjectedRegionPaint({THREE,root:head,projector,texture,maskTexture,
  landmarks, radius:.13, meshOptions:mesh=>({})});
paint.setBlend(0); // 同机位原版
paint.setBlend(1); // 局部作画
```

`texture` 为sRGB原画，`maskTexture`为不作色彩转换的参考覆盖蒙版；`landmarks`每项为
`[sourceU,sourceV,paintU,paintV]`，V向上。RBF调整采样坐标，不能把结构不同的画变成
正确透视。`meshOptions`可返回false排除网格，或按部件给`landmarkWarp:false`。
模块克隆材质时保留原`onBeforeCompile`及缓存键；否则原来的脸发光色会悄悄丢失。

两类接缝需主动看实际连续帧：

- **脸/发互相串色**：同一整头蒙版不能区分前后发束和皮肤，脸部控制点也不能拉动
  所有头发UV。本次深蓝头发可用`rejectWarm:true`退回原发色；少量蓝发误投到脸的
  区域可用`coolFallback`和`coolFallbackRegion:[u0,v0,u1,v1]`补回肤色。它们是受限
  色板的保险，不能用于任意发色，更不能全脸启用后把青色虹膜一起擦掉。优先做部件
  蒙版/可见性约束；大转头或新露面须补原画，不能靠颜色筛选无限延伸。
- **下巴/颈部色差**：整脸变暖而原颈部仍冷白会露出接缝；允许把相邻颈部纳入明确
  的修画范围，保持其几何和连接，检查蒙版也须覆盖真实修改范围。

共享检查 [review_region_paint.mjs](../scripts/review_region_paint.mjs) 接受
`--episode <dir> --config <json>`。配置包含`url,start,end,fps,width,height,output,
maskPadding,samples,labels`，画幅宽度须为偶数。剧集viewer提供：

- `renderRegionPair(t)` → `{base,paint,mask,state,baseState,headScreen}`，PNG base64；
  mask是当前帧实际可见修改表面，`headScreen`为NDC。两份state使用同一动作探针。
- `renderRegionPortrait(t,blend)` → 同角度头部诊断PNG，0原版、1作画。
- 可选`renderLegDiagnostic(t)` → `{image,feet,state}`，左右腿固定身份颜色。

输出每帧边界差分、动作状态对照、带全身和头像的A/B帧列及采样图。蒙版使用所有
非零抗锯齿覆盖；仅用50%阈值会漏掉细发尖。初次检查曾出现两个14色阶差异像素，
定位后均为蒙版值64的发尖，保留原失败报告，再按真实覆盖复核，不能直接放宽差分阈值。
数值通过不证明步态自然，仍须按左右腿身份查看前后交换、重心及脚底接触。

首次试作：一张返回1254×1254的头部原画复用2秒/60帧，原3D全身和绘画场景保留。
提示词虽指定1024与锁定轮廓，返回尺寸与下巴/鼻尖位置仍改变，实际需要控制点配准。
限定视角表面画味提升不等于自由手绘轮廓已经完成；新的脸部表演仍是后续独立工作。

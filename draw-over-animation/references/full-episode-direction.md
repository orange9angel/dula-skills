# 整集作画与局部控制

本流程用于用户已认可短样片并明确要求整片使用同一工艺。沿用已认可的声音、
身份、色板与粒子选择，补齐其余剧情阶段所需的作画资产和表演通道。

## 范围先变成完整时轴

原 `script.story` 继续提供剧情、对白与动作 cue。单集作画镜表引用这些时间，
从第 0 帧连续覆盖到末帧；输出覆盖表必须列出每段实际调用的画面路径。
已认可的二维样片可作为子镜段复用，其余窗口必须实际改造。原片仅取声音时，
在来源记录里明确区分声音与画面。不要将局部插入的完整时长视频描述为整集重制。

规划常态、蓄力、格挡、受击、恢复、站起、移动、退场以及道具状态，避免只有
大招原画却拿同一蹲姿覆盖所有对白。镜表应交代说话者、倾听者和接触因果，
而不是等间隔替换漂亮立绘。近景需要保留脸、下颌与字幕的空间关系。

## 从整人物贴片拆出真正有作用的控制

[cel-stage.js](../assets/cel-stage.js) 提供 atlas 区域提取、透明边界裁切、
局部网格表演及按原画坐标分离图层。内容方负责逐个原画的区域、头发/头部位置、
显示尺寸、固定点、前后顺序和动作时点。生成的 atlas 不保证严格均分：先看实际
像素边界；姿势或披风可能越过象限中线，机械四等分会剪掉身体。

[face-acting.js](../assets/face-acting.js) 在专用空白五官原画上绘制眉眼、视线、
眨眼、嘴型和表情。眼、口落点按角色与视角标定；嘴型输入来自最终对白包络。
模块不自动抹除已画好的脸，不适用于任意角度。全身极值姿势应有各自表情，
不能只在特写会张嘴，而全身的格挡和受击一直保持一张脸。

发梢形变应与发力、碰撞和制动有关；可叠加少量环境运动，但不断正弦摆动不等于
完整发型表演。小幅头部/发梢网格变化、受力原画换姿和独立五官属于不同通道。
逐项关闭通道并比较同一帧像素，证明执行层真的使用了它；再看实际收益。
静态源姿势可能没有三维增量，不能据此断言整条烘焙链失效，也不能用任意时刻
的变量非零冒充画面有变化。选择实际运动窗口，保留各个试点的结果。

## 行走不能依赖整张图任意拉伸

[limb-rig2d.js](../assets/limb-rig2d.js) 提供限定机位的双骨段控制与支撑目标：

```js
const feet = plantedWalk({time, startX, velocity, ground, cycle:3, lift:18});
const warp = makeLegDeformer({width,height,legs,targets,legIndex:0});
stage.place('nearLeg', {...placement, warp});
```

`legs` 的 hip/knee/ankle 为原画归一化坐标，`targets` 为相对人物落点的显示像素。
支撑脚在世界画面空间保持，抬脚段单独走弧线；靴底使用局部刚性位移避免随小腿
转动而滚动。该工具不自动判断步速、脚掌大小、接触面或正确脚型。

实作暴露了两个失败：直接按画面下半区变形会带弯手臂和披风；按最近骨段为同一
腿逐点自动选另一条腿，会在重叠处撕裂。修正为各腿独立区域与固定 `legIndex`，
身体/披风保留原层，补全移开后暴露的裤料。裁切蒙版必须覆盖原轮廓，旧层留下的
靴甲边缘会像碎片悬在空中。支撑目标数值为零漂移仍不能证明实际鞋底像素接触。

移动段末帧也需明确姿势：步态提前结束时若落回全局战斗默认姿势，会在退场前突然
蹲下。让移动保持到镜头切走，或编排专门的收步姿势；不要用提前隐藏人物掩盖跳变。

补学时参考了 [Spine 权重说明](https://us.esotericsoftware.com/spine-weights)：
权重影响顶点归属，三角形前后顺序影响自遮挡，较大的弯曲会放大原图变形。
本项目没有集成 Spine；采用的是独立腿层、明确归属与实际极值帧复验的原则。
若现有原画缺少被遮住的形状，应补图层原画或切换专用姿势，不无限拉大网格形变。

## 道具与场景接合

接触影、光色和粒子分层继续使用 `cel-integration.js`、`particle-stage.js`。
链端、盾沿等效果锚点应来自最终二维原画的手腕/接触位置；原三维坐标不直接等于
重画后的落点。镜头改变姿势时同步切换锚点，避免链条悬在拳头旁边。

道具插入镜头需要手臂继续伸出画外、盾沿压住链条等完整关系。孤立盾牌加一个
悬空前臂不能靠加影修好；可补完整接触镜头原画，再按需加震动、光色和效果。
战前完整盾、战后裂盾、固定闸心与开启闸舌分别记录状态，不让后段战损提前出现。

## 整集导出与验收

共享 pipeline 可以使用覆盖整集的镜表。`pilot.audioCopy=true` 请求复制源音轨；
整集完成后执行：

```powershell
python <skill>/scripts/verify_full_episode.py --episode <episode> --config <pipeline.json>
```

检查完整窗口、帧数/帧率/画幅、音频包与 PCM 哈希、顺序/seek、渲染来源摘要和
单集检查适配器。实际抽查必须包含所有叙事阶段、走路连续帧、受击前后、细节
表情与片尾；记录静帧、连续帧或正常速度观看的真实方式。技术通过和艺术判断
分开写，有限原画与网格表演不能声称已经达到任意角度逐帧作画的能力。

完整作画导出后只修一个短窗口时，可沿用 `replace_window.py`，以该完整作画候选为
来源，保留候选副本、原导出摘要和局部渲染记录。不要又改回三维原片作为画面来源。
使用 `verify_full_episode.py --repair-config <repair.json>` 核对最终拼接摘要、局部
顺序/seek 和合并后的来源清单；它不自动证明代码修改只影响指定窗口，仍须检查
修改范围并复看边界。修补后可由当前完整配置直接重渲，导出行为应一致。

# Cel Look（三维做的像二维）

目标：在造型与动作成立的基础上，统一轮廓、色块和时间节奏，达到约定的二维画面风格。
实现参考：`yuki_morning_battle`（sketch 实验及已知造型局限）、`yuki_beat_ad` V17
（口型平面化 + 猫描边）、`dula-engine/handdrawn/`（sketchify + BoilSystem）。这些是代码参考，不是默认合格的美术样板。

遇到球手、棍状四肢或弯曲轮廓不成立，先读 [动画作画监督](../direct-animation-craft/SKILL.md)，再处理本文件的画面风格。加描边、增加细分、抽帧不能补上缺失的造型与表演。

## 在造型与动作之后整理画面

生成角色或小雪 craft3d 风格的系统整理，联用
[曲面角色与绘制外观](../character-modeler/references/craft3d-drawn-characters.md)。
先分离几何起伏、贴图烘焙明暗与实时高光；仅更换 toon 材质不会消除前两项。

1. **轮廓线**：干净动画使用稳定、可控的外轮廓，减少内部接缝线，细节线弱于主体轮廓。速写风可使用 `sketchify()` 和 `BoilSystem`；抖动与碎线不是所有画风的默认项。线色按色板选择，暖黑或纯黑都可以。无描边风格也可能符合用户目标。
2. **色块阴影**：干净赛璐璐可从底色加一档阴影起步，按样板选择色阶和阴影色相。避免塑料高光及过多明暗切面；具体数量并非所有动画的统一标准。
   脸部先验证统一底色，再增加有形体或光源依据的阴影。固定的额头横带、双颊深色
   多边形可能读成拼色皮肤；不能把“色阶少”当作赛璐璐已经成立。脸、耳、颈和
   四肢复用肤色色板，核对受光/不受光材质混用后的实际成片颜色。
3. **脸部图形**：平面嘴、眼部贴片或局部修型有助于控制图形。按镜头检查侧脸、转头、遮挡和透视，不把所有五官永远 billboard 朝向相机。
   鼻侧、眼下等结构线应描述具体转折，细于睫毛并留断口，不能靠满脸短线制造
   “肉体感”。眼睛先区分黑瞳形状、虹膜明暗与反光；已有白点也可能在成片尺度
   读不出来。曲面脸可在既有 UV 绘制链中追加图形，继承视线和眼皮裁切，并复查
   闭眼、半闭、斜侧和最终尺寸。S1E3 `face_ink_r2` 是局部试样：眼部层次与结构线
   有限改善，不代表脸部形体、微表情或整片达到参考水平。
4. **曝光节奏**：从关键姿势与动作节拍决定一拍一、一拍二或长停格。24fps 一拍二为 12 次姿势更新，30fps 一拍二为 15 次；在 30fps 上直接 `floor(t * 12) / 12` 会产生 2/3 帧保持交替。使用输出帧号/曝光表，不能把固定 12Hz 当通用修复。
5. **各层时钟**：摄影机通常维持输出帧率；角色姿势、根位移、脸部和口型明确各自策略，检查组合后是否滑步、漂移或失同步。口型可以使用离散曝光，但必须保留声音起止和闭嘴事件，音频时间不量化。

## 检查清单（出片前逐项过）

- [ ] 剪影、关键姿势和手脚语义先成立；形变问题已归回资产或作画层处理
- [ ] 线条符合目标风格；干净线稿没有无意的毛边、碎线或内部黑圈
- [ ] 色块、阴影与角色样板一致
- [ ] 手型切换/连续变形符合镜头需求，腕口和持物接触稳定
- [ ] 脸部图形在本镜头的转面范围内成立
- [ ] 动作的受力、缓冲、停顿合理，形变服务表演
- [ ] 实际输出帧保持符合曝光设计，口型贴合声音，足部没有因时钟分离而滑动
- [ ] 同机位静帧与连续短片都已检查；技术全绿不等于审美达标

## 发梢、衣服细边的时间稳定性

先用实际成片圈出连续帧，再按顺序隔离原因：固定时间重复渲染是否一致、是否有
boil/随机时钟、共面几何或描边内漏、透明裁切阈值、亚像素细线、导出中间编码。
场景静止时的稳定不能代替人物运动时的检查；镜头移动造成的整幅差分也不能叫闪烁。

- 保持姿势、相机、灯光和最终显示尺寸相同，分别比较原版、无损中间帧、提高空间
  采样。硬 `alphaTest` 发片和不足一像素的衣服描边，即使开启 MSAA 仍可能出碎边。
  可先用长宽各 2 倍渲染，再缩回目标尺寸；不要把输出变大冒充同尺寸改善。
- PNG 或直接像素管道避免 JPEG 中间压缩再次污染高反差细边。最终编码仍须单独
  抽帧检查，不能只检查浏览器 canvas。明确记录渲染尺寸、输出尺寸、MSAA 样本数、
  透明覆盖选项和中间格式。
- `alphaToCoverage` 必须单独试验。S1E4 的固定时间重复测试中，覆盖模式出现像素
  差异，而原裁切与 2 倍采样重复稳定，因此该轮没有采用覆盖模式。这是当前管线的
  实测取舍，不是所有 GPU/材质的普遍结论。不得仅凭单张边缘更软就设为默认。
- 拆开检查男女主的头发与衣袖，再回到完整画面、连续动作和实际编码视频。对同姿态
  高采样参照的残差只能描述栅格差异；高采样本身、缩放滤镜和阴影也需检查，不能
  将残差改善百分比直接称为观感闪烁减少。静止部位不提供动态稳定性的证据。
- 保留已接受的造型、动作、镜头、声音及系列字卡；整集重导出时验证这些保留项。
  参考：S1E4 `tools/check_edge_stability.mjs`、`tools/review_edge_stability.py`。

## 翻车记录

- **道具特写与朝向摄影机的细丝（2026-10-21）**：先按旧道具位置选摄影机、
  更新带状细丝，再根据新道具位置纠正摄影机，会让细丝宽度依赖上一镜头。
  先完成道具变换和最终摄影机，再更新依赖视角的带状几何；透明变形网格同步
  更新包围球，关闭视锥剔除不能替代透明排序所需的中心。长剧1282.233秒的
  失败保留：原版从四个不同位置跳入均有明显像素差，修订后与顺序输出一致。
  这个反例应由真实输出验证，不能放宽JPEG容差掩盖几何状态差异。

- **半透明脸图叠层遇上底图缓存（2026-10-21，长剧试片）**：底层口型绘制器对
  相同状态跳过重绘，外层却每次追加半透明面颊阴影，导致相同时间重复渲染后肤色
  越来越深。缓存的是干净底图，外层每次先恢复底图再绘眼睛与细节；不能只减淡
  阴影来掩盖积累。五角色实际输出在重复20次及跳离30帧后返回均无像素差异，
  只证明状态确定性，不证明阴影形状或脸部体积合格。
  排查时避免用活跃绘图 canvas 的 `getImageData` 作为唯一证据：本次读取触发了
  浏览器栅格路径变化，抗锯齿差异造成误报。比较最终输出，在独立只读 canvas
  解码；保留原失败记录，不能通过放宽阈值制造通过。
- **脸部拼色面具（2026-10-10 S1E2 R19）**：上轮把额头和左右颊阴影硬画进
  曲面纹理，用户复看指出肤色“一片一片”。这些图并未获得审美认可，不能设为黄金样板。
  修正统一皮肤底色与材质路径、移除固定颊部/额头分区，仅保留轻量下颌—颈部区分。
  同机位斜侧/正脸与带对白近景比较后，再决定是否需要有依据的阴影。
- **正脸与后脑 UV 接缝必须断开（同轮）**：正脸使用平面投影、后脑使用常量
  皮肤采样时，不能让一个三角形跨越两套 UV。复制侧缝顶点并分开连接；否则
  三角形会扫过整个五官图，侧面出现窄楔形杂色，即使底色统一也可能露馅。
- **细化阶段必须配视觉护栏**：机械断言（闭嘴/穿模/帧数）全绿也可能观感回退。
  用黄金帧回归：监制认可版渲染关键帧存 `storyboard/golden/baseline/`（入库），
  之后在相关改动时重渲染同批帧做像素对比，超阈值出并排 diff 图。diff 只能定位变化，不能自动判断变化的美术质量。
  参考实现：`yuki_fish_musical/tools/golden_frames.mjs`（2026-09 立。
  首次实战就证明了价值：手型集被误判"改坏"，harness 对比证明它是无辜的，
  真正的发梢毛边是上一版存量问题）。
- 为便于判断原因，按造型/动作/线条组织可比较的修正。沿用用户既有授权和明确的审美反馈，普通迭代不新增逐批批准要求。
- **生成服装的平涂分区（2026-10-14 S1E4）**：颜色阈值会把褶皱阴影变成碎斑，
  单一高度裁切会误染指尖、袜子和裙腰。组合原色、骨骼区域、衣物边界和拓扑平滑，
  必须检查全身；半身镜头被桌子遮住的问题不能算已解决。绘制脸替换后的旧颌面、
  颈口和描边同步清理，详见 [曲面角色工艺](../character-modeler/references/craft3d-drawn-characters.md)。
- **配色灰淡与头发亮带（2026-10-14 S1E4 V3）**：底色偏灰且亮暗压平会显褪色；
  分部位设计底色和阴影色，在最终显示空间检查，不能只看代码中的色值。
  头发的亮面随束面组织，统一高度的横亮带容易像发箍。精修对照应包含上一版，
  具体眼型、发束框架和挂点问题见 [曲面角色工艺](../character-modeler/references/craft3d-drawn-characters.md)。
  色彩改善不等于领口、袖根语义边界已经修好。
- **整体明暗被误做成球壳明暗（2026-10-20 S1E3 R6）**：去除逐束管状高光后，
  候选用头壳径向量着色，并按固定高度增加亮带。侧后面仍像帽壳，横带又跨过
  不同束面。主束转折、交叠暗部和整团明暗需同时成立；先看实际亮面形状再查
  shader。此轮为用户指出后的诊断，尚未修复，见
  [发型多角度复核](../character-modeler/references/layered-hair-study.md)。

- sketchify 的 boil 必须由渲染时间驱动（`BoilSystem.update(time)`），
  用 wall clock 会破坏离线渲染的确定性（V17 已验证同帧逐字节一致）。
- 描边宽度是局部单位，小部件要自动收缩（sketchify 已处理）；猫背面
  尾巴线条在 0.014 下略粗，特写场景降到 0.012。
- 一拍二不要全局套：BG 平移、摄影机、角色姿势、根位移和口型按曝光设计协调，检查落脚和口型时机。
- **按既有目标选描边；风格不明确且影响工艺时再问**：sketchify（顶点抖动 + boil + 碎线）是
  "手绘速写"路线；干净动画需要连贯、粗细有设计的轮廓，不必全部等宽。
  检查当前实现中的抖动、overshoot 和硬边碎线；需要稳定线条时选用相应轮廓实现，
  不假定仅把 boil 关掉就能消除全部碎边。
  参考实现：`yuki_fish_musical/bootstrap.js` 的 `cleanOutline()`。
- 锥体尖端（双马尾末端 ConeGeometry）顶点法线分散，逆向壳会在尖端炸成
  平行细线：先把中轴顶点法线统一收到轴向（smoothConeApex）再描边。
- **凹陷脸面上的描边壳内漏（2026-10-10）**：增加鼻部体积后，法线膨胀的背面壳
  可能在鼻梁/脸颊交界形成并非外轮廓的黑折线。检查实际斜侧面，按目标移除面部壳
  或用轮廓遮罩；不能靠增加脸图分辨率修复。人物造型流程见
  [人物造型精修与动画样板](../direct-animation-craft/references/character-look-development.md)。
- **小雪造型复核（2026-09-21）**：球手、单段四肢和胶囊靴在描边后仍然缺少手脚结构。优先重做可读轮廓、弯曲控制和接触；不要把接缝毛边一律归为“手绘质感”。见 [案例诊断](../direct-animation-craft/references/yuki-morning-battle.md)。

# 入退场穿柱：先补覆盖，再修路线

S1E2 R19 的骨长、支撑脚、盾槽和命中锚点检查通过，用户仍看到夜刈从柱子中走出。
原因是这些检查根本没有覆盖角色与环境。`cameraObstacles` 只声明了铜闸，也没有被
本集角色检测消费。增加关节探针或放宽原阈值都不能解决这一漏项。

## 当前可复用执行入口

- 场景 `dula-assets/scenes/stardust/EmberTierPalaceScene.js` 在建造时登记实际柱础、
  柱身、槽饰、柱头、栏杆、铜闸、宫门和内壁对象，保存在 `navigationObstacles`。
- `dula-assets/lib/craft3d/stage-clearance.js` 读取最终可见身体、蒙皮手、甲片、武器和
  披风的真实几何。包围盒分离直接证明当前采样姿态不相交；重叠才做变换后的
  triangle/box SAT 与内部顶点深度。墨线副本与不写深度的光晕不充当实体。
- 当前窄筛仅用于实际 `BoxGeometry` 障碍；本集障碍未缩放，单位为米。
  不将其描述成任意凹网格、连续碰撞、自碰撞或通用运动求解器。变形的身体包围盒
  要随 position 版本更新，蒙皮手用当前 skeleton 重新求包围盒，不能沿用绑定态。
- 单集 `config/palace_stage_contract.json` 声明障碍数量、类别、角色和完整时间窗；
  viewer 验类别/数量，`tools/check_palace.py` 验每帧可见角色×障碍配对数、时间连续、
  有限数值和输入哈希。源码、贴图、轨迹或 contract 变动后旧报告失效。

## 以失败反例证明检查确实运行

原入场 20.43–22.30 秒被检出 57 个 30Hz 失败帧，最深约 0.340 米。
修复路线走前侧柱间通道，先行走再落脚转身；退场走后侧柱间，终点保留在栏杆内。
没有删除柱子或缩小人物来获得通过。入退场改变后按实际有限落脚重建 Foley，
配音、配乐与战斗事件时点不变。

R20 全片 60Hz / 12,780 帧评估 1,641,010 个角色—障碍配对，全部在包围盒阶段分离。
这个结果表示当前路线有净空，**不表示窄筛受过全部场景测试**。另保留原路线失败证据，
并用 `tools/probe_stage_negative.mjs` 将最终人物实体放回柱心，确认三角窄筛失败；
恢复路线通过、空障碍列表拒绝。证据在单集 `storyboard/palace_r20/`。

从这一事故推广的是“按实际风险补必检配对并做正反例”。不要给每个普通对白片
默认增加全世界全三角检查，也不要把一次 60Hz 采样写成连续时间零穿模保证。

## R24：导航实体通过，脚仍穿进近景墩座

用户指出脚穿过压盾墩座。R20—R23登记的70件导航实体没有包含墩座、两侧槽壁及
活动滑舌，原绿灯不能覆盖这个问题。场景现用 `lockSolids` 登记四件真实几何，
contract 单独声明腿、臀、护腿、靴的必检配对；盾槽有意接触继续独立验证。
不要因盾牌允许接触，顺便豁免脚或大腿。负例应恢复旧落脚并确认新检查确实报警。

本次脚点移出木墩后，小腿和大腿仍能扫入；深蹲端点通过后，半蹲过渡又失败。
检查最终变形面和整段下降/起身，不能只验踝点、腿骨线或两个端姿。身体加粗后
重新检查几何覆盖，新增臀部也要加入配对。活动滑舌需考虑真实行程包络；本例将
滑舌推向前侧、让出人体一侧，仍保留固定压盾点和锁定高度。

落脚修正的分支开关曾使摆动脚在离开障碍范围时跳约14厘米。改为连续世界坐标
映射，同一源支撑点映射到固定落点；同时检查相邻帧脚位和重心，不用瞬移换穿模。
本例另调整靠墩站位、臀部后坐与膝朝向，保持骨长及盾槽锚点；参数不是通用人体值。
源足轨道、身体朝向、脚朝向不同步时，仍需专项步态复核。

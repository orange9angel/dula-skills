# 以稳定、快速成片为目标

2026-10-14 用户最新澄清：在第三集已有质量基础上继续优化，并减少程序动画的穿模
与反复返工。预算限制针对生成视频；场景和角色可以用文生图加强。图片视觉检查按需
使用，算法用于减少无效视觉调用，并非禁止看图。不能把任一成本约束扩大成取消动作、
互动、配乐或降低美术标准。新技术只有降低重复制作成本、保持或改善成片质量才值得
接入。S1E4 R1 与 R2 的数值通过未换来用户接受，均不能作为制作成功范例。

## 图片辅助与验收分工

- 场景优先复用 hybrid-craft-scene：文生图提供背景、材质与美术细节，近景互动道具
  保留几何和接触锚点；从实际机位检查透视、遮挡、光向与贴图边缘。
- 角色以已有身份参考为基准，图片用于设计参考、服装/表情资产及确有需要的逐镜修型。
  保留成熟绑定、关键姿势和连续动作；生成一张立绘不能算完成动画角色，更不能保证
  网格无穿模。局部二维修型需跟踪动作、遮挡和切镜，不独立重绘每帧。
- 接触先按动作意图设手脚目标，再修绑定、关节路径和衣物净空；检测不能以删掉动作
  或把道具移出可达范围来获得通过。生成图片本身也不能修复三维相交。
- 算法先查可确定的问题、覆盖与失效输入，输出异常时间窗；视觉集中在新资产/新工艺
  的代表镜头、可疑接触窗口、关键表情与最终正常速度片段。修复后检查受影响部分，
  未变化且已有有效证据的部分不重复全量看图。
- 旧技能中的默认 I2V/长对白视频路线不覆盖本次预算约束，不自动转入付费生成视频。
  先用现有程序角色和口型链完成表演；是否改为图像角色须通过短试片证明连续性与收益。

## 制作顺序

1. 先保证故事能懂、角色有区别、动作和反应成立、声音清楚、可重复导出。
2. 沿用已有合格资产和表演积木。新角色先定义脸型、眼形、比例与行为习惯的区别，
   换色换发型不算完成角色设计。保留对应台词的主要姿势、转头和听者反应。
3. 新路线先出 10–20 秒代表性试片，包含两人同框、特写、主动作和听者反应。
   按实际风险做必要视觉检查；若用户另有明确零视觉要求才遵守该限制。没有观感反馈
   就标记待评，不把数值当艺术批准。
4. 只针对发现的问题升级检查。创作迭代检查受影响片段；稳定后再做一次必要的整片验证。
   导出、声画同步、已知高风险接触是常规项；不为简单对话默认建设完整全身物理系统。
5. 交付视频、简短改动和已知局限；大量 trace 留本地，不让模型读取逐帧日志。

## 缺陷与修复优先级

- 必修：阻碍理解或明显出戏的错误，例如手穿过脸、身体穿桌、掉出地面、手中物件漂走、
  台词缺失、静默嘴动，以及主要人物始终不动或无法区分。
- 结合镜头处理：可见袖身交叉、显眼关节形变、短暂脚滑。优先修骨架/绑定/挂点，
  再局部调整姿势。保留台词对应的动作意图与幅度。
- 暂缓：镜头外或正常遮挡下的微小交叠、不影响最终像素的内部几何、安全余量轻微不足。
  暂缓不等于算法证明无穿模；记录为已接受的制作取舍，不改写检测结果。
- 包围盒重叠只触发进一步判断，不能直接据此删动作。画面投影可以帮忙排序，
  无图像/深度遮挡验证时不要把“可能不可见”当成已经确认不可见。

## Three.js 生态选型（官方资料核查于 2026-10-14）

| 候选 | 适合用途 | 本项目取舍 |
|---|---|---|
| three-mesh-bvh | 网格射线、最近距离、局部相交查询、BVH 加速 | 最先做小范围兼容与成本试验；检测不改变动画，适合替代重复手写几何查询 |
| Rapier | 角色与场景的形状扫掠、走动避障、刚体与道具接触 | 当多集反复需要走动/道具碰撞时接入；不要把角色控制器当全身自碰撞修复器 |
| JoltPhysics.js | 刚体、约束、ragdoll 等更广泛物理场景 | 有大量物理互动时再比较；当前对话片不足以证明移植与调参成本值得 |

资料与边界：
- [three-mesh-bvh README](https://github.com/gkjohnson/three-mesh-bvh)：空间查询库；
  新加入的 SkinnedMeshBVH/ObjectBVH API 仍可能变化。不要只凭库名宣称动画网格自动支持。
- [API](https://github.com/gkjohnson/three-mesh-bvh/blob/master/API.md)：静态变换可复用 BVH；
  顶点形变需 refit 或烘焙后更新；大变形会使树质量降低。StaticGeometryGenerator 能烘焙
  蒙皮/变形，仍须计入更新时间。表面相交、最近距离、实体包含是不同查询，不能互相冒充。
- [Rapier 运动学刚体](https://rapier.rs/docs/user_guides/javascript/rigid_bodies/)：直接指定的
  运动学轨迹不受接触力自动纠正，仍需查询或控制器。
- [角色控制器](https://rapier.rs/docs/user_guides/javascript/character_controller/)：调整整体位移；
  内置控制器只支持平移，不解决关节姿势和旋转。碰撞响应与好看的动画需要另外衔接。
- [Jolt JS](https://github.com/jrouwe/JoltPhysics.js)：WASM 接口需要管理对象生命周期。
  [Three.js Jolt addon](https://threejs.org/docs/pages/JoltPhysics.html) 与
  [Rapier addon](https://threejs.org/docs/pages/RapierPhysics.html) 提供接入入口，不能等同完整角色方案。

本次是文档和现有管线评估，尚未接入或实测这些库的端到端提速；不要声称某库已经快几倍。
Three.js 现有版本须读本地依赖并与锁定库版本核对；不为试用擅自升级整条渲染链。

## 性价比如何验收

主指标是「每分钟用户可接受成片的总制作时间和费用」，不是穿入深度或告警数量。
质量底线包括人物辨识度、主要动作保留、听者反应、声画可用性。达不到底线的片段不算产量。

同一段已锁定的动作、人物、镜头与音频，对比：A 无自动修正，B 轻量风险检测，
C 候选库/局部修正。相同输入下先比较检测结果、耗时与误报；自动修正另比较动作保留及观感。
A 与 B 仅检测不同，最终姿势应一致；不要拿静止版和活动版比较而把差异归因于算法性能。

记录一次性接入时间（按预计复用集数摊销）、每轮执行时间、真实缺陷/误报、修复轮数、
人工与模型调用成本、最终可接受时长。CPU 运行、模型读报告和视觉调用成本分开记录；
脚本跑 2430 帧不等于模型读 2430 张图。没有实际调用费用数据就写未知。

可以先用「防穿模人工/模型修复预算约占单段制作的 10–15%，连续两轮局部修复后复盘」
作为试验上限，不是统计结论或统一标准。低成本自动检查不必硬塞进同一时间配额。
超预算且没有改善观看体验时，停止扩张专项，选择已验证动作/绑定、局部摄影调整或记录轻微瑕疵。
明显核心缺陷不能因为到达配额就冒充修复成功；可换成熟资产/动作而不牺牲剧情功能。

收益判断：节省的返工和复用成本，应大于接入摊销、运行、误报处理与画面退步的成本。
表演退步即使几何更干净也不能自动算正收益。优先减少试错轮数，而不只是让一次查询更快。

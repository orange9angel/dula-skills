# 本地控制与生成动作混用

当用户选择混合动作路线时，以实际表演效果决定每段来源：已有程序控制自然、稳定的
动作继续复用；复杂动作或反复调不好的一段交给已授权的生成后端，再做节奏、衔接和
场景接触修正。不要因为有会员就把所有小动作重新生成，也不要为了保持纯程序路线
长期交付僵硬表演。图生视频与生成三维动作是不同费用项，分别遵守用户预算。

## 接入顺序

1. 从剧情确定动作意图、左右肢体、目标物、支撑脚、接触时点和时长；已有单集以
   `.story` 为时间权威。先用短动作验证，保存原始生成文件与收费任务回执。
2. 统一绑定姿态、米制尺度、骨名和正前向。导出器改变骨轴时用绑定相对的世界旋转
   重定向，不能直接复制同名骨骼的局部四元数。逐级更新父节点；手指编号须保留。
3. 对明确的动作阶段做时间映射，衔接处渐入渐出；保留预备、接触和缓冲。根据需要
   选择全身、上半身或局部骨骼，明确 root motion 的归属；不要一边锁脚一边重复叠加根移动。
4. 生成动作没有自动获得剧集的几何约束。保留可读姿势，用末端 IK、接触时序与局部路径
   修正道具/场景关系。手腕目标相同不能证明手掌、指尖和袖口没有穿插。
5. 表情、视线、口型、头发跟随与身体动作分别接入，再协调到同一表演。无 morph 的身体
   GLB 不会因为播放了生成动作就获得面部表现；小型本地脸部补丁也不等于完整表情模型。

## 本次实证与边界

S1E4：Tripo 生成的擦臂动作已导出并重定向到保留原 UV 的 16 万面角色。独立身体试片
可播放，放进教室却出现手穿桌沿；递/拿罐还出现满握时正常、过渡时穿罐约 42mm。
修复要覆盖接近、抓住、移动和退出，不只抽取满握帧。调整路径不能牺牲表演来换取绿灯。

共享代码在 `dula-assets/lib/craft3d/`：`imported-performer.js`、`retargeted-motion.js`、
`skinned-samples.js`。`table-hand-clearance.js` 是从桌后伸手的有限路径约束，按当前
蒙皮手顶点软启动修正；不是通用物理引擎，不处理任意障碍、所有衣物或完整自碰撞。

数值检查记录真实采样覆盖、输入哈希和顺序/跳转一致性；换模型后旧角色探针必须重接。
代表性近景检查虹膜、嘴角、手掌朝向、衣物和接触，连续片段检查衔接及修正是否突跳。
只通过桌/罐采样检查时，报告该范围通过，不得称整片“零穿模”或“动画质量已达标”。
